# 02 — 쓰기 유스케이스의 명시적 트랜잭션 소유권 통일

**What to build:** 데이터베이스 쓰기가 포함된 모든 최상위 유스케이스가 하나의 명시적인 트랜잭션 경계를 소유한다. 인증 코드 발급과 교환의 기존 성공·실패 동작을 보존하면서 수동 commit/rollback이 흩어지지 않게 하고, 저장소와 하위 helper는 호출자가 만든 트랜잭션 안에서만 작업한다.

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 현재 존재하는 모든 쓰기 유스케이스는 데이터베이스 접근 전에 정확히 하나의 명시적인 트랜잭션을 시작한다.
- [ ] Kakao 사용자 조회와 같은 외부 네트워크 호출은 데이터베이스 트랜잭션을 시작하기 전에 완료한다.
- [ ] 로그인 완료 시 계정 생성 또는 인증 시각 갱신과 일회용 인증 코드 저장이 하나의 트랜잭션으로 commit된다.
- [ ] 인증 코드 교환 성공 시 일회용 코드를 소비하는 변경이 commit되고 액세스 토큰이 반환된다.
- [ ] 존재하지 않는 코드, PKCE 불일치 또는 토큰 발급 실패 시 변경 사항이 rollback되고 일회용 코드는 소비되지 않는다.
- [ ] 만료된 인증 코드는 정리 변경이 commit된 뒤 기존과 동일한 공개 오류가 반환된다.
- [ ] 저장소와 하위 helper는 트랜잭션을 시작하거나 commit/rollback하지 않는다.
- [ ] 읽기 전용 유스케이스에는 명시적인 트랜잭션 시작을 강제하지 않는다.
- [ ] 서비스 테스트와 실제 데이터베이스 통합 테스트가 성공, rollback, 만료 코드 정리 경계를 검증한다.
- [ ] 공개 API 스키마와 응답 계약은 변경되지 않는다.
