# 01 — JWT 인증 컨텍스트와 계정 조회 책임 분리

**What to build:** Bearer 인증은 데이터베이스에 접근하지 않고 JWT에서 확인한 계정 식별자를 불변 인증 컨텍스트로 전달한다. 현재 계정 조회 API는 이 컨텍스트를 사용해 계정을 조회하며, 기존 성공 응답과 인증 오류 계약을 그대로 유지한다.

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] Bearer 토큰이 없거나 유효하지 않으면 기존 공개 인증 오류를 반환하고 계정 저장소에 접근하지 않는다.
- [ ] 유효한 Bearer 토큰은 ORM 객체가 아닌 `account_id`가 담긴 불변 인증 컨텍스트를 만든다.
- [ ] 인증 컨텍스트를 만드는 dependency는 데이터베이스 세션이나 계정 저장소에 의존하지 않는다.
- [ ] 현재 계정 조회 API는 인증 컨텍스트의 `account_id`로 계정을 조회하고 기존과 동일한 성공 응답을 반환한다.
- [ ] 토큰은 유효하지만 해당 계정이 존재하지 않으면 기존과 동일한 공개 인증 오류를 반환한다.
- [ ] 읽기 전용 계정 조회 유스케이스는 명시적인 쓰기 트랜잭션을 열지 않는다.
- [ ] 공개 API 스키마와 응답 계약은 변경되지 않는다.
- [ ] API 경계의 component test가 정상 조회, 누락·잘못된 토큰, 존재하지 않는 계정을 검증한다.
