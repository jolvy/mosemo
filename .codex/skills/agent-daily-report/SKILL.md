# 에이전트 일일 보고서

## 입력
보고서 실행기(`.codex/reports/run_daily.py`)가 이 본문 뒤에 작업 지시를 붙여 넘긴다.

- 집계 JSON(`aggregate.json`): 이번 구간(`interval`)과 7일 추세(`trend`)의 숫자. 숫자는 실행기가 보고서 표로 이미 넣으므로 판단의 근거로만 인용한다.
- 세션 기록 목록: 작업 폴더 `.work/sessions/`의 복사본과 원래 경로의 대응.
- 패널 리뷰 `unreadable` 세션: 리뷰 결과 파일에 쓴 흔적은 있지만 본문을 꺼내지 못한 세션 ID. 세션 기록에서 리뷰 지적을 직접 확인해 분류한다.

## 출력 형식
세 절 제목만 `##`로 이 순서대로 쓰고 각 절에는 판단 부분만 쓴다. 다른 `##` 제목을 쓰지 않는다. 숫자 표(세션 수, 차단, 규칙별 건수, 일별 추세)를 다시 쓰지 않는다.

```markdown
## 1. 결과
판단값

| 분류 | 건수 | 세션 ID | 예시 한 줄 |
| --- | --- | --- | --- |

## 2. 최근 며칠의 양상

## 3. 개선해야 할 점
```

1. `## 1. 결과`: 표 위에 "판단값"이라고 적고 이번 구간 분류 표를 쓴다. 분류는 리뷰 지적 종류, 사용자 정정, 권한 거부, 같은 실패의 반복이다. 열은 분류, 건수, 세션 ID, 예시 한 줄이다.
2. `## 2. 최근 며칠의 양상`: 같은 규칙·같은 분류가 2일 이상 또는 2세션 이상 나온 반복 문제를 쓴다. 없으면 없다고 쓴다.
3. `## 3. 개선해야 할 점`: 반복 문제마다 근거(지표 값, 세션 ID)와 바꿀 하네스 위치(파일 경로, 규칙·절)를 쓴다. 기계 지표가 근거인 문제를 판단값이 근거인 문제보다 먼저 쓴다.

## 판단 기준
- 사용자 정정: 사용자가 에이전트의 직전 행동·결과를 되돌리거나 바로잡으라고 한 메시지.
- 권한 거부: 도구 호출이 사용자·정책에 의해 거부된 기록.
- 같은 실패의 반복: 같은 세션에서 같은 오류·같은 hook 차단 사유가 2회 이상 나온 것.
- 리뷰 지적 종류: 리뷰 보고의 지적을 정확성·공개 계약·테스트 누락·책임 위치·저장소 규칙·보안 등 내용으로 묶은 것.
- 세션 기록은 `Grep`으로 먼저 좁힌 뒤 필요한 부분만 `Read`한다.
- 에이전트 간 비교: 한쪽 에이전트의 편집 줄(`interval.by_agent_model`의 `edit.lines`)이 0이면 편집 통과율을 에이전트 사이에서 비교하지 않고 "비교 불가(편집 줄 없음)"로 적는다. Codex `PostToolUse`가 `exec` 안의 `apply_patch`에 발화하는지 확인되지 않았기 때문이다.

## 금지
- 세션 기록은 작업 폴더 `.work/sessions/`의 복사본만 읽는다. 다른 경로를 읽거나 경로를 지정하지 않은 검색으로 작업 폴더 밖을 읽지 않는다.
- 파일을 쓰지 않는다. 저장소·Git 상태를 바꾸지 않는다.
- 외부에 게시하지 않는다.
- 하네스(`AGENTS.md`, Skill, agent, hook, 검사기)를 직접 고치지 않는다. 바꿀 위치와 이유만 3절에 쓴다.
