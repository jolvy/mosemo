# 에이전트 지표 로그 강화와 일일 분석 보고서

## 목적과 사용자

저장소 소유자는 실제 mosemo 개발 중에 자연스럽게 쌓이는 로그를 근거로 하네스
(`AGENTS.md`, Skill, agent, hook, 검사기)의 개선점을 찾는다. 목표는 일관된 기준과
일관된 코드 스타일이다. 어느 회사의 모델을 쓰든 같은 기준으로 비슷한 결과가 나와야 한다.

행위자:

- 개발 에이전트: Claude Code와 Codex. 저장소 hook이 이들의 세션에서 지표를 기록한다.
- 보고서 실행기: 소유자의 Mac에서 하루 한 번 예약 실행되어 지표 로그와 세션 기록을 분석한다.
- 소유자: 보고서를 읽고 하네스 변경을 결정한다.

## 현재 구현 범위

- 지표 로그 강화
  - 편집 시점 기계 검사 위반을 기록한다.
  - Codex 세션도 Claude Code와 같은 필드로 기록한다.
  - 작업 식별자(브랜치)를 기록한다.
- 일일 분석 보고서: 로컬 예약 실행, 로컬 Markdown 파일, macOS 알림

## 기능 요구사항

### 지표 로그

- FR-1 편집 직후 hook(`post_edit_feedback.py`)이 Ruff 검사를 마치면, 남은 위반의 규칙 ID별
  건수를 지표 로그에 한 줄로 기록한다. 위반이 0건이어도 기록한다. 편집 시점의 통과율이
  Stop 시점보다 앞선 신호이기 때문이다.
- FR-2 Stop 줄과 편집 줄은 공통 필드를 가진다: `at`, `event`(`edit`·`stop`), `session`,
  `agent`, `model`, `harness_rev`, `harness_dirty`, `branch`. Stop 줄은 기존 필드
  (`skills`, `result`, `session_blocks`, `failed`, `rules`)를 유지한다.
- FR-3 `agent`가 `codex`인 줄도 `model`과 `skills`를 채운다. Codex 세션 기록
  (`~/.codex/sessions/YYYY/MM/DD/*.jsonl`)에서 읽는다.
- FR-4 `harness_dirty`는 언제나 불리언이다.
- FR-4a 리뷰 에이전트(code-reviewer·domain-reviewer·security-auditor)는 보고의 첫 줄을 고정 형식
  `REVIEW high=0 medium=2 low=1` 형식(각 값은 해당 심각도 지적 건수)으로 쓴다. 에이전트·모델과 무관하게 같은 형식이다.
- FR-4b 리뷰가 끝나면 지표 로그에 `event`=`review` 줄을 기록한다. 필드는 공통 필드와 함께
  `reviewer`(리뷰 에이전트 이름), `findings`(심각도별 건수), `format_ok`(첫 줄 형식 준수 여부)다.
  Agent 도구로 띄운 리뷰 subagent는 subagent 종료 이벤트에서, 별도 세션으로 띄운 리뷰는
  그 세션의 Stop에서 마지막 보고를 읽는다. 형식을 지키지 않은 보고도 `format_ok`=`false`,
  `findings`=`null`로 기록한다.

### 일일 분석 보고서

- FR-5 이 Mac에서 하루 한 번 예약 실행된다.
- FR-6 마지막 보고서 이후 새 세션이 기준 수 미만이면 분석을 건너뛰고 보고서를 만들지 않는다.
- FR-7 숫자 집계는 결정적 스크립트로 만든다. 같은 로그를 넣으면 같은 숫자가 나온다.
  - 그날 결과: 세션 수, 에이전트·모델별 세션 수, Stop 결과 분포, 차단·`capped` 수,
    규칙 ID별 편집 시점·Stop 시점 위반 수
  - 최근 7일 추세: 같은 지표의 일별 값, 에이전트·모델별 값, `harness_rev`가 바뀐 시점
- FR-8 판단이 필요한 신호는 세션 기록을 읽어 분류한다. 리뷰 지적의 내용·종류(건수·심각도는 FR-4b의 기계 지표),
  사용자 정정, 권한 거부, 같은 실패의 반복이 여기에 속한다. 이 값은 판단이 들어간 값이라고
  보고서에 표시하고, 기계 검사 숫자와 섞지 않는다.
- FR-9 보고서는 세 절로 쓴다.
  1. 결과: FR-7 그날 값과 FR-8 그날 분류
  2. 최근 며칠의 양상: 7일 추세와 반복되는 문제
  3. 개선해야 할 점: 반복 문제마다 근거(지표 값, 세션 ID)와 하네스의 어디를 바꿀지
- FR-10 보고서는 저장소 밖 로컬 폴더에 날짜별 Markdown 파일로 쓴다. 작성이 끝나면 macOS
  알림으로 경로를 알린다. 실행이 실패해도 실패 알림을 보낸다.

## 정책과 불변식

- 기계 검사 지표를 가장 중요한 개선 신호로 본다. 판단이 들어간 신호는 그다음이다.
- 지표 기록 실패는 편집 hook과 Stop 판정에 영향을 주지 않는다(기존 AC-2와 같은 원칙).
- 보고서와 그 원문 데이터는 이 Mac 밖으로 내보내지 않는다. GitHub Issue·댓글·PR에
  보고서를 올리지 않는다(저장소가 공개 저장소다). 예외는 분석에 쓰는 모델 API 호출뿐이다.
- 보고서 실행기는 저장소 파일과 Git 상태를 바꾸지 않는다. `gh`·`git push`를 쓰지 않는다.
- 고정 평가 세트는 쓰지 않는다(#186 승인 기록 「평가 세트 폐기」).

## 예외와 경계 조건

- 여러 worktree와 세션이 같은 지표 로그 파일에 동시에 줄을 붙인다. 줄이 섞이거나
  잘리면 안 된다.
- 세션 기록을 읽을 수 없거나 형식이 다르면, 해당 필드는 `null`·빈 목록으로 두고 줄은 기록한다.
- 예약 시각에 Mac이 잠자기 상태였으면 깨어난 뒤 한 번 실행한다. 놓친 날을 몰아서
  여러 번 실행하지 않는다.
- 보고서 실행이 모델 사용량 한도·네트워크 오류로 실패하면 보고서를 만들지 않는다.
  실패 알림을 보내고 다음 예약 때 다시 시도한다.
- Herdr 리뷰 패널처럼 리뷰만 하는 세션도 Stop 줄을 남긴다. 개발·리뷰 세션 구분은 FR-8
  분류에서 한다. Agent 도구로 띄운 subagent는 자기 Stop 줄이 없다(`SubagentStop` 미등록).
  리뷰 지적은 부모 세션 기록에서 읽는다.

## 비기능 요구사항

- 편집 hook의 기존 시간 제한(10초) 안에서 기록을 마친다.
- 보고서 1회 비용은 모델 API 환산으로 기록하고 보고서에 적는다. 상한 수치는 미결정이다.

## 확장 방향

- 다른 회사의 에이전트 CLI를 추가할 때는 그 세션 기록 파서와 hook 등록만 더하면 된다.
  로그 필드와 보고서 집계는 바꾸지 않는다.
- 새 기계 검사기를 추가하면 규칙 ID가 편집·Stop 줄의 `rules`에 자연히 들어간다.

## 제외 범위

- 고정 평가 세트와 `claude -p` 반복 실행 비교(삭제는 별도 Issue)
- GitHub로 보고서 게시, 다른 기기로 동기화
- CI 결과 수집
- 보고서가 하네스를 직접 고치는 것. 개선점 제안까지만 한다.

## 인수 조건

- AC-1 Python 파일을 편집해 Ruff 위반이 남으면 지표 로그에 `event`=`edit` 줄이 추가되고,
  `rules`에 해당 규칙 ID별 건수가 있다. 위반이 없으면 `rules`가 비어 있는 `edit` 줄이 추가된다.
- AC-2 Claude Code·Codex 세션 기록 fixture를 넣으면 각각 `agent`·`model`·`skills`가 채워진
  줄이 만들어진다(harness 테스트).
- AC-2a 리뷰 보고 fixture(형식 준수, 형식 위반, 지적 0건)를 넣으면 `event`=`review` 줄의
  `reviewer`·`findings`·`format_ok`가 각각 기대값이다(harness 테스트).
- AC-2b 세 리뷰 에이전트 지시문에 고정 첫 줄 형식이 있다(harness 테스트가 지시문 파일에서 형식 문자열을 확인).
- AC-3 모든 줄의 `harness_dirty`가 불리언이고 `branch`가 있다(harness 테스트).
- AC-4 같은 지표 로그 fixture로 집계 스크립트를 두 번 실행하면 출력이 같다.
- AC-5 마지막 보고서 이후 새 세션이 기준 수 미만인 fixture에서는 보고서 실행기가 분석
  없이 종료하고 보고서 파일을 만들지 않는다.
- AC-6 보고서 실행이 끝나면 보고서 폴더에 그날 날짜의 파일이 생기고 세 절의 제목이 있다.
  실패하면 실패 알림 명령이 호출된다.
- AC-7 보고서 실행 중 저장소의 `git status --porcelain` 출력이 바뀌지 않고, 실행 명령의
  허용 도구에 `gh`·`git push`가 없다.

## 확인된 사실·가정·미결정

확인된 사실(2026-11-07):

- 지표 로그는 Stop 줄만 기록한다. 편집 hook은 Ruff 위반을 에이전트에게 알리기만 하고 기록하지 않는다.
- 실제 개발 세션의 Stop 차단은 0건이다. 위반은 편집 시점에 대부분 고쳐진다.
- 지표 로그는 2026-11-06 08:02 UTC부터 쌓였다. 그 뒤 mosemo-server를 작업 폴더로 쓴 Codex
  세션은 없다. 그래서 Codex hook이 실제로 기록하는지는 확인되지 않았다.
- `.claude/settings.json`에는 `PostToolUse`·`Stop` hook만 등록돼 있다. 리뷰 subagent의 종료는 기록되지 않는다.
- 리뷰 에이전트 지시문(`.codex/agents/*.toml`)은 심각도순 보고만 요구하고 심각도 이름·형식을 정하지 않는다.
- 저장소 `jolvy/mosemo`는 공개 저장소다.

가정:

- Codex 세션 기록 형식(`session_meta`, `response_item` 등)이 버전이 바뀌어도 크게 달라지지 않는다.

확정(소유자, 2026-11-07):

- 건너뛰기 기준 수: 마지막 보고서 이후 새 세션 5개 미만이면 건너뛴다.
- 예약 시각: 매일 09:00(Asia/Seoul).
- 보고서 폴더: `~/mosemo-reports/`(저장소 밖).
- 집계 스크립트와 실행기는 저장소(`.codex/` 아래)에 두고 하네스와 함께 버전 관리한다. 예약 등록(launchd)은 소유자 Mac에 설치한다.
- 리뷰 지적을 기계 지표로 기록한다. 지적 내용 분류는 일일 보고서가 한다.

미결정:

- 보고서 1회 비용 상한: 처음 몇 번 실측한 뒤 정한다.
- Codex에 subagent 종료에 해당하는 hook 이벤트가 있는지: 미확인. Plan 단계에서 공식 문서나 실험으로 확인하고, 없으면 Codex 리뷰는 부모 세션 Stop에서 읽는 방식으로 정한다.
