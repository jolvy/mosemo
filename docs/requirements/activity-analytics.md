# 활동 분석: 사용 시간·사용 대상 전환·집중 이탈·라벨 전환

## 목적과 사용자

Mosemo 사용자는 하루 동안 어떤 앱과 사이트에 시간을 썼는지, 사용 대상을 얼마나
자주 오갔는지, 집중 세션에서 의도한 작업을 벗어나게 만든 사용 대상과 그 근거가
무엇인지, 확정한 활동 의미가 얼마나 자주 바뀌었는지 알고 싶다. 관찰 타임라인은
사실을, 라벨은 사용자가 확정한 의미를, 집중 세션은 사용자가 의도한 작업을 담고
있으므로 분석은 이 세 원천을 결합하되 각각의 권위를 바꾸지 않는다.

- 행위자: 인증된 계정 사용자와 그 계정의 macOS 클라이언트.
- 분석은 관찰 사실과 사용자 확정만 근거로 삼고 AI 추정이나 미관찰 시간의 추정을
  결과에 넣지 않는다.

## 현재 구현 범위

다음 분석 데이터 7종을 모두 제공한다(2026-11-01 C1~C6, 2026-11-09 C7 범위 확정).

| ID | 분석 데이터 | 단위 | 원천 |
| --- | --- | --- | --- |
| C1 | 앱 사용 시간 순위와 사용 대상 사용 시간 순위 | 계정 시간대의 날짜 | 관찰 활동 구간 |
| C2 | 날짜별 사용 대상 전환 횟수와 목록 | 계정 시간대의 날짜 | 관찰 활동 구간 |
| C3 | 세션별 사용 대상 전환 횟수와 목록 | 완료된 집중 세션 | C2, 집중 세션 |
| C4 | 세션 분석 시간의 집중·이탈·확정 미분류·판정 대기·불투명·미관찰 구성 | 완료된 집중 세션 | 관찰 활동 구간, 확정 라벨, 집중 세션 |
| C5 | 방해 앱별 진입 횟수·이탈 시간 | 완료된 집중 세션 | C4와 같음 |
| C6 | 집중 이탈별 이탈 근거 | 집중 이탈 | C4와 같음 |
| C7 | 라벨 전환 횟수와 목록 | 계정 시간대의 날짜, 완료된 집중 세션 | 관찰 활동 구간, 확정 라벨, 집중 세션 |

집중 세션 완료 시 선택적으로 전달하는 **일시중지 구간**을 저장하고 분석에서
제외한다.

세션 분석과 오늘의 일간 통계는 조회할 때 원천에서 계산한다. 지난 날짜의 일간
통계(C1·C2·C7)만 저장해 두고, 원천이 바뀐 날짜는 다시 계산한다. 생성 흐름은 [ADR 0016](../adr/0016-compute-activity-analytics-on-read-and-store-daily-stats.md)이
정하고, 공개 경로·응답 형태와 테이블 구조는 엔지니어링 계획에서 정한다.

## 기능 요구사항

### 사용 대상 식별

- FR-1: **앱**은 상세 문맥 관찰 활동 구간의 `context.app.bundleId`가 `captured`인
  값으로 식별한다. 표시 이름은 같은 bundleId의 해당 기간 최신 관찰 이름을 쓴다.
- FR-2: **사용 대상**은 구간마다 다음 규칙으로 정한다.
  - 브라우저 앱이고 탭 URL을 수집했으면 그 URL의 **사이트**(eTLD+1, 예:
    `https://m.youtube.com/watch?v=…` → `youtube.com`).
    - `http`·`https` URL인데 eTLD+1을 정할 수 없는 호스트(IP 주소, `localhost`처럼 점
      없는 이름, `github.io`처럼 공개 접미사 자체)는 호스트 그대로(포트 제외)가
      사이트다. 예: `http://192.168.0.1:8080/` → `192.168.0.1`.
    - `http`·`https`가 아니거나 호스트가 없는 URL(`chrome://settings`, `about:blank`,
      `file:///…`)은 사이트가 없으며 그 브라우저 앱이다.
    - scheme 바로 뒤에 `://`가 없으면(Firefox는 주소창 값을 scheme 없이 보낸다)
      `^[a-z][a-z0-9+.-]*:` 뒤 첫 글자가 숫자가 아닌 URL(`about:blank`, `javascript:`, `data:`)은
      사이트가 없으며 그 브라우저 앱이고, 그 밖(`meet.google.com/x`, `localhost:8000/docs`)은
      `https://`를 붙여 위 규칙을 적용한다. scheme은 대소문자를 가리지 않는다.
  - 브라우저 앱이지만 URL이 비식별화·미수집이면 그 브라우저 앱.
  - 브라우저가 아니면 그 앱.
  - 원본 URL은 바꾸지 않는다. 사이트는 분석에서만 파생하며 scheme을 붙이는 것도 분석
    안의 해석이다.
  - 사이트의 비교·저장 키는 호스트를 IDNA 2003으로 바꾼 ASCII 소문자이고 끝의 점은
    지운다. 표기만 다른 같은 호스트(NFC·NFD, punycode, 전각)는 같은 사이트다. 화면에는
    유니코드로 바꿔 보여 준다.
- FR-3: bundleId가 `absent`·`unavailable`인 구간은 `앱 미확인`으로, 불투명 활동은
  `불투명 활동`으로 별도 집계하며 어떤 앱·사용 대상에도 귀속하지 않는다.

### 앱·사이트 사용 시간 (C1)

- FR-4: 선택한 타임라인 날짜에 대해 두 순위를 제공한다. 각 순위는 시간 내림차순,
  같은 시간이면 식별자 오름차순으로 정렬한다.
  - **앱 순위**: 앱별 관찰 활동 시간. 같은 앱의 사이트별 시간을 모두 앱에 더한다.
  - **사용 대상 순위**: 사용 대상별 관찰 활동 시간.
- FR-5: 날짜 경계를 가로지르는 구간은 계정 시간대의 그 하루와 겹치는 시간만
  합산한다. 일광 절약 시간 전환일의 하루는 23시간 또는 25시간이다.
- FR-6: 열린 관찰 활동 구간은 `lastObservedAt`까지만 합산하고 현재 시각까지 늘리지
  않는다. 수집 공백과 60초를 초과한 관찰 침묵은 어떤 시간에도 포함하지 않는다.
- FR-7: `앱 미확인`·`불투명 활동` 시간과 날짜 전체의 관찰 활동 시간을 함께 제공해
  앱 합계와 구분한다.

### 사용 대상 전환 (C2·C3)

- FR-8: 사용 대상 전환 1회는 경계가 맞닿은 두 관찰 활동 구간(관찰 문맥 전환)에서
  양쪽 사용 대상이 모두 식별되고 서로 다른 경우다.
- FR-9: 다음은 세지 않는다.
  - 같은 사용 대상 안의 창·탭·제목·URL 변화(같은 사이트의 다른 페이지 포함).
  - 다른 브라우저의 같은 사이트(`Chrome: youtube.com → Safari: youtube.com`).
  - 수집 공백이나 60초 초과 침묵을 사이에 둔 변화.
  - 어느 한쪽이 `앱 미확인`이거나 불투명 활동인 변화.
- FR-10: 전환 시각은 뒤 구간의 시작 시각이다. 날짜별 전환(C2)은 전환 시각이 속한
  타임라인 날짜에 속한다.
- FR-11: 각 전환은 이전 사용 대상, 다음 사용 대상, 전환 시각, 이전 사용 대상의
  체류 시간을 제공한다. 체류 시간은 전환 직전까지 이전 사용 대상으로 맞닿아 이어진
  구간들의 길이 합이며 공백·침묵·다른 사용 대상에서 끊긴다. 짧은 체류 전환을
  걸러내는 최소 시간은 두지 않는다.
- FR-12: 세션별 전환(C3)은 C2 전환 중 전환 시각이 세션의 각 **작업 구간** 안에
  있는 것이다. 작업 구간은 세션 분석 시간을 이루는 구간이며 시작과 끝을 모두
  제외한다. 즉 세션 시작 순간, 일시중지가 시작·종료되는 순간, 세션 종료 순간의
  전환은 세지 않는다. 이전 사용 대상 체류 시간은 C2 값을 그대로 쓰며 세션 경계로
  자르지 않는다.

### 집중 판정 (C4)

- FR-13: 분석 대상은 완료된 집중 세션이다. **세션 분석 시간**은 시작~종료에서
  일시중지 구간을 뺀 시간이다. 세션 분석 시간과 겹치는 관찰 활동 구간은 겹친
  부분만 사용한다.
- FR-14: 세션 분석 시간의 각 조각을 다음 순서로 판정한다.
  1. 불투명 활동 → **불투명**.
  2. 유효한 확정이 없음 → **판정 대기**. 확정은 확정 당시의 구간 version이 현재
     구간 version과 같을 때만 유효하다.
  3. 미분류로 확정 → **확정 미분류**. 이탈로 보지 않는다.
  4. 확정 라벨 = 세션 라벨 → **집중**.
  5. 확정 라벨 ≠ 세션 라벨 → **이탈**.
- FR-15: 세션별로 위 다섯 판정의 시간 합계와 **미관찰** 시간(세션 분석 시간 − 다섯
  판정 합계, 수집 공백·침묵·관찰 없음)을 제공한다. 여섯 값의 합은 세션 분석
  시간과 같다.
- FR-16: 집중 이탈은 이탈 활동이 시작된 시점부터 집중 활동으로 돌아오거나 세션
  분석 시간이 끝날 때까지 이어진 이탈 활동의 묶음이다. 확정 미분류·판정 대기·
  불투명 활동·미관찰 시간·일시중지 구간은 집중 이탈을 끝내지 않지만 이탈 시간에
  포함하지도 않는다. 세션별 집중 이탈 건수를 함께 제공한다.

### 방해 앱 (C5)

- FR-17: **진입 횟수**: 집중 이탈을 시작하는 이탈 판정 구간은 바로 앞 구간과 같은
  사용 대상이어도 그 사용 대상에 1회를 더한다. 집중 이탈 중에는 이탈 판정 구간이 바로
  앞 구간과 다른 사용 대상이면 그 사용 대상에 1회를 더한다. 그래서 진입 횟수의 합은
  집중 이탈 건수 이상이다. 같은 사용 대상 안의 탭·창 변화는 다시 세지 않는다. 직전 구간은 세션
  작업 시간 안의 바로 앞 구간이며 불투명 활동은 건너뛰고 판정 대기는 건너뛰지 않는다.
  미관찰·일시중지 시간은 구간이 아니므로 그 앞 구간과 비교한다. 앱 미확인 이탈 구간끼리는
  같은 `앱 미확인`으로 비교한다.
- FR-18: **이탈 시간**: 이탈 판정 구간의 시간을 사용 대상별로 합한다. 사용 대상이
  없는 앱 미확인 이탈은 `앱 미확인` 항목으로 모은다. 판정 대기·확정 미분류·불투명·
  미관찰·일시중지 시간은 넣지 않는다.
- FR-19: 세션별로 방해 앱 목록(사용 대상별 진입 횟수·이탈 시간)을 제공한다. 진입
  횟수의 합은 집중 이탈 건수와 다를 수 있으며, 화면은 "이탈 중 열어 본 횟수"처럼
  이탈 건수와 구분되는 문구를 쓴다.

### 이탈 근거 (C6)

- FR-20: 각 집중 이탈에 다음 관찰 근거를 제공한다.
  - 시작·끝 시각.
  - 진입 문맥: 첫 이탈 구간의 사용 대상·창 제목·URL·확정 라벨(원본 문맥 그대로,
    의미 정규화 없음).
  - 직전 집중 활동의 사용 대상. 세션 시작 직후의 이탈처럼 직전 집중 활동이 없으면
    값이 없다.
  - 세션 시작 후 이탈 시작까지 경과한 세션 분석 시간(일시중지 제외).
  - 이탈 시간(이탈 판정 시간만).
  - 이탈 중 사용 대상 전환 횟수: 이탈 안의 C2 전환만 세고, 이탈을 시작한 전환과
    집중으로 돌아온 전환은 제외한다. 안과 밖은 시각이 아니라 구간 순서로 가르므로
    진입·복귀 시각과 같은 시각의 0초 구간 사이 전환도 센다.
  - 집중 활동으로 복귀했는지 여부.
- FR-21: 알림·피로 같은 동기는 추정하지 않는다.

### 라벨 전환 (C7)

- FR-22: 라벨 전환 1회는 경계가 맞닿은 두 관찰 활동 구간이 모두 유효한 확정
  라벨(미분류 제외)을 가지고 그 라벨이 서로 다른 경우다. 0초 구간도 전후 구간이
  될 수 있다.
- FR-23: 판정 대기·확정 미분류·불투명 활동·수집 공백·60초 초과 침묵이 사이에
  끼면 세지 않는다. 판정 대기 구간을 건너뛰어 앞뒤 확정 라벨을 비교하지 않는다.
- FR-24: 각 전환은 이전 라벨, 다음 라벨, 전환 시각(뒤 구간의 시작)을 제공한다.
  날짜별 전환은 전환 시각이 속한 날짜에, 세션별 전환은 FR-12와 같은 작업 구간
  기준으로 속한다.

### 일시중지 구간

- FR-25: 집중 세션 완료 요청은 선택적으로 일시중지 구간 목록 `[시작, 종료)`를
  받는다. 기존 클라이언트처럼 목록이 없으면 일시중지 정보가 없는 세션으로 저장한다.
- FR-26: 일시중지 정보가 없는 세션은 시작~종료 전체를 세션 분석 시간으로 사용하고,
  분석 결과에 일시중지 정보가 없었음을 표시한다.

### 갱신

- FR-27: 분석 조회 결과는 언제나 조회 시점의 원천(관찰 구간 재구성과 늦게 도착한
  관찰, 라벨 확정·정정, 집중 세션 완료)을 반영한다. 세션 분석과 오늘의 일간 통계는
  조회할 때 처음부터 계산한다. 변경분을 더하지 않으며 과거 결과를 별도로 고정하지
  않는다.
- FR-28: 지난 날짜의 일간 통계(C1·C2·C7)는 (계정, 계정 시간대 날짜) 단위로 저장한다.
  원천 변경이 그 날짜에 닿으면 다시 계산 표시를 남기고, 배치가 그 날짜를 처음부터
  다시 계산해 통째로 교체한다. 표시가 남아 있거나 옛 지표 정의 또는 옛 계정 시간대로
  계산된 날짜는 조회할 때 저장 행 대신 다시 계산한 값을 돌려준다. 계정 시간대를 바꾸면
  지난 날짜도 새 시간대의 날짜 경계로 다시 계산한다.
- FR-29: 분석 조회 응답은 결과의 기준 시각으로 마지막 관찰 시각(`observed_through`)을
  함께 제공한다. 조회 시각이나 계산 시각은 기준 시각으로 쓰지 않는다. 화면은 "HH:MM까지
  관찰된 기록 기준"으로 보여 주고, 기준 시각이 지금보다 30분 넘게 이르면 기기에서 아직
  올라오지 않은 기록이 있을 수 있다고 안내한다. 결과가 언제나 최신 원천을 반영하므로
  "갱신 대기" 상태는 두지 않는다.
- FR-30: 조회 때 계산이 실패한 날짜를 포함하는 분석 조회는 요청 전체를 공통 오류
  응답으로 실패시킨다. 저장된 옛 결과로 대신 응답하거나 그 날짜만 뺀 결과를 돌려주지
  않는다.

## 정책과 불변식

- 분석은 관찰 타임라인·확정 라벨·집중 세션을 읽기만 하며 원천 데이터를 바꾸지 않는다.
- 이탈 판정과 라벨 전환에는 유효한 사용자 확정 라벨만 쓴다. 라벨 제안은 판정
  대기로만 반영한다.
- 수집 공백과 관찰 침묵을 활동·전환·이탈로 추정하지 않는다.
- 불투명 활동은 앱·문맥 정보를 어떤 분석 결과에도 노출하거나 귀속하지 않는다.
- 일시중지 구간의 시간은 세션 분석 시간, 세션별 전환, 집중 이탈에서 제외한다.
- 계정의 분석은 그 계정의 데이터만 사용한다.
- 다음 등식은 같은 원천 스냅샷에서 항상 성립한다.
  - C1: 앱 순위 합 = 사용 대상 순위 합 = 관찰 활동 시간 − 앱 미확인 − 불투명.
  - 저장된 일간 통계 = 같은 원천에서 그 날짜를 조회 때 계산한 결과.
  - C4: 여섯 시간의 합 = 세션 분석 시간.
  - C5: 사용 대상별 이탈 시간 합 + 사용 대상이 없는 이탈 시간 = C4 이탈 시간.
  - C3 ⊆ C2, C7 세션별 ⊆ C7 날짜별(세션이 걸친 날짜들의 합).
- 라벨은 사용자가 확정한 대로가 정답이다. 서버는 확정 라벨의 진위를 확인하거나 드러내지
  않으며, 세션 안·밖 라벨 불일치처럼 확정을 의심하는 지표를 만들지 않는다.
- 90일이 지난 원천을 S3로 옮길 때는 "S3로 복사 → 객체 확인 → 라벨 확정·구간 삭제 → 원본
  레코드 삭제" 순서를 지킨다. 라벨 확정은 원본 레코드에 `ON DELETE CASCADE`로 걸려 있어
  복사 전에 원본을 지우면 확정이 함께 사라진다. 지우는 행은 객체 확인을 통과한 행이며, 아직
  90일이 지나지 않은 날짜가 (지원하는 어느 시간대로든) 읽는 경계 행(자정을 넘는 구간, 거슬러
  읽히는 앞 구간)은 그 날짜를 옮길 때까지 DB에 남긴다. 다시 계산 표시가 남은 날짜는 옮기지 않는다.
- 90일이 지난 시각의 원천은 바꾸지 않는다. 계정마다 동결 시각을 두고 줄이지 않으며(시간대를
  바꿔도), 그보다 이른 범위를 바꾸는 늦은 관찰·라벨 확정·정정은 거부한다.
- 90일이 지난 날짜의 조회가 돌려주는 옛 값은 계산 기준(정의·시간대)만 다르고 원천은 지금과 같다.
- S3 이관본의 구간 문맥은 URL의 경로·query를 지우고 scheme 분류와 호스트만 남긴다. 앱
  bundleId·이름과 창·탭 제목은 남긴다.
- 삭제됨 상태의 계정은 로그인과 분석 조회를 할 수 없다. 이미 발급된 토큰의 조회도 거절한다.
  삭제됨이 된 뒤에는 그 계정의 관찰·라벨 확정을 받아들이지 않고, 일간 통계 배치도 저장하지 않는다.

## 분석 화면 원칙

분석 화면은 macOS 클라이언트 범위다. 서버는 아래 원칙을 지킬 수 있는 값을 응답에 넣는다.
지표 왜곡과 측정 한계의 근거는 [활동 분석 위험](../activity-analytics-risks.md)에 있다.

- P-1: 판정 대기·확정 미분류를 숨기거나 접지 않는다. C4 여섯 값을 한 막대에 늘 함께
  그린다. 예: `집중 32분 · 다른 라벨 8분 · 미분류 5분 · 아직 확정 안 함 12분 · 비공개 0분 · 기록 없음 3분`.
- P-2: 비율 하나로 요약하지 않는다. `집중률 80%`(집중 ÷ (집중 + 이탈))는 판정 대기를
  분모에서 빼므로 확정을 미룰수록 올라간다.
- P-3: 목표선·연속 기록·좋음/나쁨 색을 쓰지 않는다. 전환이 줄면 초록, 늘면 빨강 같은 평가
  색과 "어제보다 개선" 문구를 쓰지 않는다.
- P-4: 사실 동사로 쓴다. "관찰된", "확정한", "열어 본"을 쓰고 "딴짓", "산만", "원인",
  "방해받음"은 쓰지 않는다. 이탈은 "세션 라벨과 다른 라벨로 확정한 시간"이다.
- P-5: 이탈 건수와 진입 횟수를 구분한다(FR-19). 예: `이탈 2번, 이탈 중 열어 본 앱·사이트 5번`.
- P-6: C6에서 직전에 쓰던 사용 대상을 원인처럼 보이게 하지 않는다. 화살표 대신 시간 순서로
  나열한다. 예: `14:05 코딩(VSCode) 중 · 14:05 youtube.com 열림 · 7분 뒤 VSCode로 돌아옴`.
- P-7: 함께 봐야 해석이 맞는 값을 같은 화면에 둔다. 다른 탭이나 상세 화면으로 내리지 않는다.

  | 지표 | 같은 화면에 함께 보여 줄 값 |
  | --- | --- |
  | C1 대상별 시간 | 수집되지 않은 시간, 불투명·앱 미확인 시간, URL 없는 브라우저 앱 시간 |
  | C2 전환 수 | 5초 미만 체류 전환 수, 수집 공백·관찰 침묵 횟수 |
  | C3 세션 전환 수 | 일시중지 횟수·시간 |
  | C4 이탈 시간 | 판정 대기·확정 미분류 시간 |
  | C5 대상별 진입 | 세션 밖 같은 사용 대상의 C1 시간, 브라우저 앱·앱 미확인 항목 |
  | C7 라벨 전환 수 | 확정률(판정 대기 시간) |

- P-8: 짧은 왕복을 숨기지 않되 나눠 보여 준다. 짧은 왕복 필터는 두지 않고(2026-11-11 결정),
  "5초 미만 머문 전환 N회"를 함께 보여 준다. 예: `전환 312회 (그중 5초 미만 체류 171회)`.

값이 바뀌는 이유별 안내:

- 지표 정의 version이 올라가면 version마다 앱 안에서 한 번 공지한다. 무엇이 바뀌었고 어떤
  값이 달라질 수 있는지 쓴다. 예: `11월 20일부터 Firefox 주소를 사이트로 나눠 셉니다. 지난 날짜의 사이트 순위와 전환 횟수가 바뀔 수 있습니다.`
- 계정 시간대를 바꾸기 전에 지난 모든 날짜를 새 시간대로 다시 나눈다는 확인 문구를 보여 준다.
- 늦게 도착한 관찰과 라벨 정정 같은 원천 변경은 따로 안내하지 않고 기준 시각(FR-29)만 보여 준다.

## 예외와 경계 조건

- 0초 관찰 구간도 전환의 이전·다음 구간이 될 수 있다. A→B(0초)→C는 전환 2회다.
- 같은 사용 대상으로 돌아오는 A→B→A는 전환 2회다. 몇 초짜리 왕복도 센다.
- 0초 이탈 구간도 집중 이탈 1건(이탈 시간 0초)이다.
- 세션 시작 직전부터 이어진 구간은 세션 시작 시각부터의 겹친 부분만 판정한다.
- 작업 구간은 `[시작, 끝)`이다. 세션 시작·일시중지 종료 시각의 0초 구간은 판정하고(0초 이탈이면
  이탈 1건), 일시중지 시작·세션 종료 시각의 0초 구간은 판정하지 않는다.
- 열린 관찰 활동 구간은 세션 분석(C3~C7)에서도 `lastObservedAt`까지만 쓰고 그 뒤는 미관찰이다.
- 끝이 없는 수집 공백은 구간 목록의 마지막에만 온다. 날짜 읽기는 `COALESCE(ended_at,
  last_observed_at) >= 날짜 시작` 조건으로 고른 구간과 그 첫 구간에서 같은 사용 대상으로 맞닿은 앞
  구간들(거슬러 읽기)이며, 그 사이를 연속 범위로 읽지 않는다.
- 자정을 넘는 세션은 집중 세션 계약대로 시작 날짜에 속한다. 세션 분석은 날짜와
  무관하게 세션 분석 시간 전체를 사용한다.
- 자정에 정확히 걸친 0초 구간과 자정을 넘는 연속 체류도 날짜별 결과에서 빠지거나
  잘리지 않는다.
- 세션 라벨이 이후 보관되어도 세션 라벨 기준 판정은 유지한다.
- 일시중지 구간은 세션 시작~종료 안에 있어야 하고 서로 겹치지 않아야 하며, 위반
  시 완료 요청을 거절한다. `workSeconds`와의 정합 검증 방식은 미결정이다.
- 완료 후 늦게 도착한 유효한 관찰은 다음 조회부터 분석에 반영된다.
- 진행 중 세션은 분석하지 않는다.

## 비기능 요구사항

- 같은 원천 데이터에 대한 분석 결과는 조회 순서·전송 순서·배치 실행 순서와 무관하게
  결정적이다.
- 원천 변경이 멈추면 유한한 배치 실행 안에 남은 다시 계산 표시가 0개가 된다.
- 공개 계약은 Pydantic 모델·camelCase·공통 오류 응답을 따르고 OpenAPI를 갱신한다.
- 설계 목표 규모는 하루 활성 사용자 1천 명이다.
- 분석 화면 하나의 조회(하루의 C1·C2·C7 또는 세션 하나, 저장 행 대신 원천에서 계산하는
  경우 포함)는 서버 응답 시간이 p95 300ms 이하, p99 500ms 이하다. 5단계에서 t3.small과
  1천 명 × 3일 데이터로 측정한다. 부하 모델의 조회 빈도는 분석 화면 새로고침 정책을
  따른다: 지난 날짜는 자동으로 새로고침하지 않고(화면을 열 때와 날짜를 바꿀 때만), 오늘은
  60초마다 새로고침하며, 화면이 보이지 않으면 멈춘다.
- 일간 통계 배치는 5분 주기를 기본값으로 두고 측정 뒤 조정한다([ADR 0016](../adr/0016-compute-activity-analytics-on-read-and-store-daily-stats.md)
  「실패·재처리」).
- 일간 통계 배치에서 한 날짜가 계속 실패해도 다른 날짜의 저장을 막지 않는다. 같은
  날짜의 재시도는 유한하며, 그 뒤 그 날짜는 격리되어 운영자가 해제할 때까지 배치가
  다시 시도하지 않는다.
- 원본 관찰 기록은 90일 보관한다. 90일이 지나면 원본 활동 레코드(와 배치 영수증 등 원본
  부속 기록)는 삭제하고, 다시 계산에 필요한 구간·라벨 확정·집중 세션은 S3로 압축해
  옮긴다. 그 뒤 그 날짜에는 저장된 일간 통계(C1·C2·C7)만 조회에 쓴다. S3 이관본은 URL의
  경로·query를 지우고(「정책과 불변식」), 서버 측 암호화로 저장하며, 이관·삭제 배치의 역할만
  접근한다. S3 경로는 계정별로 나눈다.
- 일간 통계(C1·C2·C7, C2의 초 단위 전환 목록 포함)는 계정이 있는 한 보관하고 계정을 삭제할
  때 함께 지운다.
- 계정 삭제: 삭제를 요청하면 계정을 곧바로 "삭제됨"으로 바꿔 로그인과 조회를 막는다. 새벽
  4시(KST)에 하루 한 번 도는 삭제 배치가 삭제됨 계정의 DB 데이터(원본 활동 레코드, 구간,
  라벨 확정, 집중 세션, 일간 통계, 다시 계산 표시)를 나눠 지우고, 같은 배치에서 그 계정의
  S3 이관본도 지운다. 처리 기한은 요청 뒤 다음 새벽 배치다(최대 약 24시간 + 처리 시간).
  운영 로그와 DB 백업은 각자의 보관 기간이 끝나면 사라진다. S3 버킷에 버전 관리를 켜면 옛
  버전 객체 만료 규칙을 함께 두고, 백업 보관 기간(계정 삭제 뒤 데이터가 남는 최대 기간)은
  개인정보 처리방침에 적는다. 5단계에서 계정 하나의 삭제 시간과 그동안 다른 조회의 지연을
  잰다. 지금 코드에는 계정 삭제 API가 없으며, 이 의무는 계정 삭제 기능과 함께 구현한다.
- 일간 통계 배치의 실패나 지연은 활동 수집·타임라인 갱신·라벨 확정·세션 완료를
  막지 않고 조회 결과의 정확성도 바꾸지 않는다. 다시 계산 표시 기록은 원천과 같은
  트랜잭션에서 실행되므로 그 실패는 원천 요청을 실패시킨다([ADR 0012](../adr/0012-notify-cross-context-changes-with-in-process-domain-events.md)).

## 확장 방향

다음은 현재 범위가 아니지만 기존 결과의 의미를 바꾸지 않고 추가할 수 있어야 한다.

- 전환 판정: 최소 체류 시간 필터, 짧은 왕복 제외.
- 기간: 주·월·연 통계. 저장된 일간 통계를 더해 만든다.
- 질의: 일간 통계를 근거로 한 LLM 답변. 창 제목·URL의 외부 전달을 따로 검토한다.
- 90일 지난 날짜의 활동: S3 이관본에 남긴 창·탭 제목과 호스트로 과거 상세 조회, LLM 답변,
  라벨 다시 추천을 할 수 있다.
- 이탈 원인: 사용자 사유 입력, 세션별 허용 앱 지정.

## 제외 범위

- 주간·월간 등 날짜를 넘는 기간 집계(2026-11-01 생략 결정).
- 하루 단위 방해 앱 집계.
- AI에 의한 이탈 판정·원인 추정.
- 사용자 사유 입력, 세션별 허용 앱 목록.
- 진행 중 세션의 실시간 분석과 이탈 알림.
- 집중도 점수 같은 합성 지표.
- 확정 라벨의 진위를 가리는 지표(예: 같은 사용 대상의 세션 안·밖 라벨 불일치).
- 사이트보다 세밀한 URL·경로 단위 사용 시간과 전환.
- 여러 활성 Device의 겹치는 기록 해결(관찰 타임라인의 단일 순서를 그대로 따른다).
- 활동 구간(타임라인) projection 생성 방식 변경과 legacy 활동 경로.
- macOS 화면 구현.

## 확인된 사실·가정·미결정

### 확인된 사실

- 관찰 활동 구간의 context에는 앱 bundleId·이름, 창 제목, 브라우저 탭 제목·URL이
  필드별 수집 상태와 함께 있다. 불투명 활동은 식별 정보가 없다.
- 확정 라벨은 확정 당시의 `segment_version`을 저장하며
  (`ActivityLabelConfirmation.applies_to`), 구간이 재구성되면 그 확정은 현재 구간에
  적용되지 않는다.
- 공개 API가 받는 시간대는 `Asia/Seoul`·`America/New_York`·`UTC` 세 개다. Python
  `zoneinfo`의 598개 시간대 모두 1990-01-01~2040-01-01의 UTC 오프셋이 15분의
  배수다(2026-11-10 주 단위 표본 측정).
- 집중 세션은 라벨 하나와 `workSeconds` 합계만 저장하며 일시중지 구간은 저장하지
  않는다. 일시중지 중 관찰은 세션에 연결하지 않는다.
- 라벨 대시보드는 확정값만 합산하고 날짜 경계를 넘는 구간은 겹친 시간만 합산한다.
- 도메인 이벤트는 지금 `AccountCreated`만 정의되어 있다. 일간 통계의 다시 계산
  표시가 구독할 `TimelineChanged`·`LabelConfirmed`는 ADR 0012에 따라 첫 구독자인
  분석과 함께 정의한다. 세션 분석은 조회 때 계산하므로 `FocusSessionCompleted`를
  구독하지 않는다.
- 90일 지난 날짜에 정의·시간대 변경이 닿으면 S3에서 원천을 읽어 다시 계산하고, 끝날 때까지는
  저장된 값에 "이전 기준" 표시를 붙여 응답한다. 상태 모델 전수 검사(2026-11-13)로 경계 행 보존,
  전날·다음 날 파일 읽기, 줄지 않는 동결 시각을 더한 설계를 확인했다
  ([ADR 0016](../adr/0016-compute-activity-analytics-on-read-and-store-daily-stats.md) 「90일 지난 날짜」).
  하루보다 긴 구간·거슬러 읽기 사슬의 실제 길이는 7단계에서 확인한다.

### 사용자 결정 (2026-10-25)

- 이탈 판정은 세션 라벨과 다른 확정 라벨이며 미확정은 판정 대기로 분리한다.
- 이탈 원인은 관찰 근거만 제공한다.
- 일시중지 구간을 완료 요청으로 받아 저장하고 분석에서 제외한다.
- 확정 미분류는 이탈이 아니다. 이탈로 보면 "확인했지만 분류하지 않은" 활동이
  방해로 집계되어 미분류 확정을 꺼리게 만든다.
- 불투명 활동·앱 미확인 구간이 낀 변화는 전환으로 세지 않는다. 불투명 활동은
  같은 대상일 수도 있어 세면 과대 집계되고, 세지 않으면 일부 실제 전환이 누락된다.

### 사용자 결정 (2026-11-01)

- 분석 데이터 범위는 C1~C6 전체다.
- 분석 결과는 조회 시 계산하지 않고 저장한다. 생성 방식은 Kafka 이벤트 대신
  재계산 표시와 배치 job으로 하며 갱신 주기는 5분이다. (2026-11-12 대체)
- 주간·월간 집계는 이번 범위에서 생략한다.

### 사용자 결정 (2026-11-03)

- 분석 결과는 15분 UTC 분석 칸 단위(C1·C2·C7)와 세션 단위(C4~C6)로 저장한다.
  (2026-11-12 대체)
- 열린 구간은 사용 시간에 `lastObservedAt`까지 포함한다.
- 식별 단위는 앱(bundleId)이 아니라 사용 대상(사이트 또는 앱)이다. 사용 시간은
  앱 순위와 사용 대상 순위를 모두 제공한다.
- 세션별 전환은 C2 전환을 세션 작업 구간으로 거른 것이며 세션 시작·일시중지 종료
  순간의 전환은 세지 않는다.
- 방해 앱은 이탈을 시작한 사용 대상만이 아니라 이탈 중 진입한 모든 사용 대상이며,
  진입 횟수와 이탈 시간을 사용 대상별로 제공한다. 이전 가정(방해 앱 = 이탈 진입
  앱)을 대체한다.
- 이탈 근거의 진입 문맥은 분석 결과에 복사해 저장한다. (2026-11-12: 세션 분석을
  저장하지 않으므로 복사 저장도 하지 않는다)

### 사용자 결정 (2026-11-09)

- 라벨 전환(C7)을 범위에 포함한다.
- 재계산 표시는 ADR 0012의 도메인 이벤트 handler가 같은 트랜잭션에서 기록한다.

### 사용자 결정 (2026-11-11)

[지표 명세](../activity-analytics-metrics.md)의 경계 사례·반례·측정을 근거로 정했다.

- 날짜별 분석 칸은 `COALESCE(ended_at, last_observed_at) >= 칸 시작`으로 읽는다.
  (2026-11-12: 칸 대신 날짜 경계에 같은 조건을 쓴다)
- 이전 사용 대상 체류 시간은 같은 대상의 연속 체류 시간이다.
- 0초 이탈도 집중 이탈 1건이다.
- 앱 미확인 이탈은 C5의 `앱 미확인` 항목으로 모으고, 진입 판정에서 불투명 활동은
  건너뛴다.
- 짧은 왕복 필터는 두지 않는다. 실제 6일 기록에서 5초 미만 왕복을 빼면 전환의 55%가
  사라진다.

### 사용자 결정 (2026-11-11~12)

- 설계 목표 규모는 하루 활성 사용자 1천 명이며 재설계를 허용한다.
- 세션 분석과 오늘의 일간 통계는 조회할 때 계산한다. 근거: 실제 기록의 가장 바쁜
  하루(구간 497개)의 C1~C7 계산이 중앙값 20ms, 최대 69ms(Python 프로토타입, DB 읽기
  제외).
- 지난 날짜의 일간 통계(C1·C2·C7)만 (계정, 날짜) 단위로 저장한다. 나중의 주간·월간·
  연간 통계와 LLM 답변의 바탕이며, 정정이 반영되어야 하므로 변경 표시와 배치로
  다시 계산하고 표시가 남은 날짜는 조회 때 계산한다.
- 주간·월간·연간 통계와 LLM 답변은 이번 범위에 넣지 않는다.

### 사용자 결정 (2026-11-12)

- eTLD+1을 정할 수 없는 URL의 사용 대상(FR-2): `http`·`https`이면 호스트 그대로(포트
  제외)를 사이트로, 그 밖의 URL과 호스트 없는 URL은 브라우저 앱으로 센다. 로컬 개발
  서버(`localhost`)나 공유기 화면(IP 주소)은 일반 탐색과 구별되는 사용 대상이고,
  `chrome://`·`about:` 같은 브라우저 내부 화면은 사이트가 아니라 브라우저 사용이다.

### 사용자 결정 (2026-11-13)

- 복귀 없이 끝난 집중 이탈의 끝은 세션 분석 시간의 끝이다(FR-16). 세션이 일시중지
  상태로 끝나면 일시중지가 시작된 시각에 이탈도 끝난다.
- scheme 없는 URL(FR-2, 지표 명세 D9): scheme 바로 뒤에 `://`가 없으면 `^[a-z][a-z0-9+.-]*:`
  뒤 첫 글자가 숫자가 아닐 때만 비웹(브라우저 앱)이고, 그 밖은 `https://`를 붙여 해석한다.
  scheme은 대소문자를 가리지 않는다. 기록일 리허설에서 Firefox URL이 scheme 없이 왔다.
- 독립 참조 구현과 프로토타입이 같게 고른 해석을 명세로 고정한다(지표 명세 D10): 작업
  구간 `[시작, 끝)`의 0초 구간, C5 직전 조각이 미관찰·일시중지를 건넘, 앱 미확인 이탈끼리
  다시 진입으로 세지 않음, 열린 구간은 C3~C7에서도 `lastObservedAt`까지, C6 이탈 중 전환은
  구간 순서로 가름.
- 입력 계약: 끝이 없는 수집 공백은 구간 목록의 마지막에만 온다. 날짜 읽기는 D1 조건으로
  고른 구간과 D2로 거슬러 읽은 구간이다(지표 명세 D1·D2).
- C5 진입(FR-17, 지표 명세 D11): 집중 이탈을 시작하는 이탈 구간은 바로 앞 구간과 같은
  사용 대상이어도 진입 1회다. "진입 횟수 합 ≥ 집중 이탈 건수"를 지킨다.
- 국제화 도메인(FR-2, 지표 명세 D12): 사이트 키는 IDNA 2003 ASCII 소문자로 통일하고 화면
  표시는 유니코드로 바꿔 보여 준다.
  IDNA 변환이 실패한 호스트도 정규화한 키에 PSL을 적용하고, scheme 판정은 ASCII 범위(숫자 0~9, `mailto:`처럼
  뒤 글자가 없으면 비웹)이며, 끝 점은 변환 전 `.`·`。`·`．`·`｡`, 변환 뒤 ASCII `.`이다(지표 명세 D9·D12).
- 일간 통계 저장·갱신 프로토콜([ADR 0016](../adr/0016-compute-activity-analytics-on-read-and-store-daily-stats.md)
  「일간 통계 프로토콜」): 정의 변경 재처리는 옛 정의 날짜마다 표시를 추가하고, 저장
  트랜잭션은 현재 정의를 `FOR SHARE`로 확인한 뒤 저장(guard)과 표시 삭제를 함께 하며,
  분석 조회는 REPEATABLE READ READ ONLY 트랜잭션 하나로 읽는다. 표시 version은 전역
  시퀀스이고 표시 쓰기는 계정 잠금 안에서, 배치는 잠금 없이 표시를 읽고 계산 동안 잠금을
  쥐지 않는다. 표시는 DB에만 있고 화면 상태는 없다. 4단계 상태 모델 전수 탐색(원천 변경
  2회·배치 2개·날짜 1개·조회 1개)에서 불변식 위반이 없었다.
- 일간 통계 배치의 실패·재처리([ADR 0016](../adr/0016-compute-activity-analytics-on-read-and-store-daily-stats.md)
  「실패·재처리」): 기존 배치 프로세스에서 5분마다 실행하고, 계정 시간대 자정 1시간 뒤부터
  지난 날짜로 처리한다. 선점은 짧은 트랜잭션에서 lease를 쓰고 계산 동안 잠금을 쥐지
  않는다. 시도는 선점 때 세고, 실패하면 5분·30분·2시간·12시간·24시간 뒤 다시 시도하며,
  6회째에 격리한다. 계산 예외로 격리된 날짜를 포함한 조회는 요청 전체를 공통 오류로
  실패시키고 저장된 옛 결과로 응답하지 않는다(FR-30). 정의 변경은 마이그레이션으로 정의
  행을 올리고 배포 확인 직후 표시를 추가하며, 재처리 속도는 환경 변수로 조절한다. 원천
  표시를 정의 재처리 표시보다 먼저 처리한다. 격리 해제는 운영 SQL로 한다. 수치는 측정 전
  기본값이다.
- 조회 응답 예산(비기능 요구사항): 분석 화면 하나의 조회는 원천 계산 경우를 포함해 서버
  응답 p95 300ms 이하, p99 500ms 이하다.
- 분석 화면 새로고침: 지난 날짜는 자동 새로고침하지 않고(열 때와 날짜를 바꿀 때만), 오늘은
  60초마다, 화면이 보이지 않으면 멈춘다. 화면 구현은 macOS 클라이언트 범위다.
- 원본 보관: 원본 관찰 기록은 90일 보관한다. 90일 뒤 원본 활동 레코드(와 배치 영수증 등
  원본 부속 기록)는 삭제하고, 구간·라벨 확정·집중 세션은 S3로 압축해 옮긴다. 1천 명 기준
  원본은 하루 약 5.8GB(측정한 1명·1일 약 5.8MB에서 추정)라 기간 없이 보관할 수 없다.
- 5단계 성능 테스트 데이터는 1천 명 × 3일이다(EBS 30GB 안). 1천 명 × 7일은 측정한 크기로
  약 41GB라 대체했다.
- 계정 시간대를 바꾸면 지난 날짜도 새 시간대로 다시 계산한다([ADR 0016](../adr/0016-compute-activity-analytics-on-read-and-store-daily-stats.md)
  「일간 통계 프로토콜」). 저장 행에 계산 때의 시간대를 두고, 시간대 변경은 계정 잠금 안에서
  저장 행이나 표시가 있는 날짜와 그 앞뒤 하루에 다시 계산 표시를 남긴다.
- 계정 삭제(비기능 요구사항): 요청 즉시 "삭제됨"으로 바꿔 로그인·조회를 막고, 새벽 4시(KST)
  하루 한 번 배치가 DB(원본·구간·확정·세션·일간 통계·표시)와 S3 이관본을 나눠 지운다. 기한은
  다음 새벽 배치다. 운영 로그·백업은 보관 기간 만료로 사라진다. 조건: S3 경로 계정별 분리,
  옛 버전 객체 만료 규칙, 백업 보관 기간을 처리방침에 명시.
- S3 이관 문맥(「정책과 불변식」): 창·탭 제목은 남기고 URL의 경로·query만 지운다(scheme
  분류·호스트 유지). 90일 뒤에도 무슨 활동을 했는지 남겨 과거 상세·LLM 답변·라벨 다시 추천에
  쓰고, 사이트 규칙을 바꿔도 다시 계산할 수 있게 한다. S3는 서버 측 암호화, 접근은 배치 역할만.
  이관 순서는 복사 → 확인 → 확정·구간 삭제 → 원본 삭제다.
- 일간 통계(C2 초 단위 전환 목록 포함)는 계정이 있는 한 보관하고 계정 삭제 때 함께 지운다.
  주간·월간·연간 통계와 LLM 답변의 바탕이기 때문이다.
- 화면 기준 시각(FR-29)은 `observed_through`(마지막 관찰 시각)다. 조회 시각을 쓰면 늦게 올라온
  기록 때문에 값이 비어 있어도 방금 계산한 것처럼 보인다(측정 수신 지연 중앙값 41.6시간).
- [분석 화면 원칙](#분석-화면-원칙) P-1~P-8을 요구사항에 둔다. 위험 근거는
  [활동 분석 위험](../activity-analytics-risks.md)에 둔다.
- 라벨은 사용자가 확정한 대로가 정답이다(「정책과 불변식」). 세션 안·밖 라벨 불일치 같은 진위
  확인 지표는 만들지 않고 확장 방향에도 넣지 않는다. 딴짓 구간을 세션 라벨로 확정하는 것은
  사용자 권한이다.
- 값이 바뀔 때의 안내(「분석 화면 원칙」): 정의 version마다 앱 안 공지 1회, 시간대 변경 전 확인
  문구. 원천 변경은 안내 없이 기준 시각만 보여 준다.
- 90일 지난 날짜의 다시 계산(F-3 상태 모델 결과에 따른 보완): 경계 행은 다음 날짜를 옮길 때까지
  DB에 남기고, S3 다시 계산은 전날·그 날짜·다음 날 이관본과 DB에 남은 행을 읽으며, 동결은 계정별
  동결 시각(줄지 않음)으로 판정한다.

### 가정 (측정 전)

- 계정-하루 구간을 읽는 DB 시간을 더해도 조회 지연이 예산(p95 300ms·p99 500ms) 안이다.
  5단계에서 t3.small로 측정한 뒤 확정한다.
- 사이트(eTLD+1) 계산 라이브러리의 동작은 최소 재현으로 확인하기 전까지 가정이다.

### 미결정

- 일시중지 구간 합계와 `workSeconds`의 정합 검증(엄격 일치, 허용 오차, 검증 없음).
  추천: 초 단위 내림 오차만 허용. 엔지니어링 계획에서 기존 클라이언트 값으로 확인한다.
- 일간 행에 그날 시작한 세션의 지표 합(C4 시간, 이탈 건수, C5)을 함께 둘지(기간 통계의
  바탕).
- eTLD+1 라이브러리와 Public Suffix List 갱신 방식.
