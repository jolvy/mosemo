# 활동 분석: 컨텍스트 스위칭·앱 사용 시간·집중 이탈

## 목적과 사용자

Mosemo 사용자는 하루 동안 앱을 얼마나 자주 오갔는지, 어떤 앱에 시간을 가장 많이
썼는지, 집중 세션에서 의도한 작업을 벗어나게 만든 앱과 그 근거가 무엇인지 알고
싶다. 관찰 타임라인은 사실을, 라벨은 사용자가 확정한 의미를, 집중 세션은 사용자가
의도한 작업을 담고 있으므로 분석은 이 세 원천을 결합하되 각각의 권위를 바꾸지
않는다.

- 행위자: 인증된 계정 사용자와 그 계정의 macOS 클라이언트.
- 분석은 관찰 사실과 사용자 확정만 근거로 삼고 AI 추정이나 미관찰 시간의 추정을
  결과에 넣지 않는다.

## 현재 구현 범위

- 계정 시간대의 날짜별 **앱 사용 시간** 순위.
- 계정 시간대의 날짜별, 그리고 완료된 집중 세션별 **컨텍스트 스위칭** 횟수와
  전환 목록.
- 완료된 집중 세션별 **집중 이탈**과 이탈을 일으킨 **방해 앱**, 그리고
  관찰 근거로 구성한 **이탈 근거**.
- 집중 세션 완료 시 선택적으로 전달하는 **일시중지 구간**의 저장과 분석 제외.

공개 경로·응답 형태·저장 방식(조회 시 계산 또는 projection)은 엔지니어링 계획에서
정한다.

## 기능 요구사항

### 앱 식별

- FR-1: 앱은 상세 문맥 관찰 활동 구간의 `context.app.bundleId`가 `captured`인
  값으로 식별한다. 표시 이름은 같은 bundleId의 해당 기간 최신 관찰 이름을 쓴다.
- FR-2: bundleId가 `absent`·`unavailable`인 구간은 `앱 미확인`으로, 불투명 활동은
  `불투명 활동`으로 별도 집계하며 어떤 앱에도 귀속하지 않는다.

### 앱 사용 시간

- FR-3: 선택한 타임라인 날짜에 대해 앱별 관찰 활동 시간을 합산해 내림차순으로
  제공한다. 같은 시간이면 bundleId 오름차순으로 정렬한다.
- FR-4: 날짜를 가로지르는 구간은 해당 날짜와 겹치는 시간만 합산한다.
- FR-5: 열린 관찰 활동 구간은 `lastObservedAt`까지만 합산한다. 수집 공백과
  60초를 초과한 관찰 침묵은 어떤 앱 시간에도 포함하지 않는다.
- FR-6: `앱 미확인`·`불투명 활동` 시간과 날짜 전체의 관찰 활동 시간을 함께 제공해
  앱 합계와 구분한다.

### 컨텍스트 스위칭

- FR-7: 컨텍스트 스위칭 1회는 경계가 맞닿은 두 관찰 활동 구간(관찰 문맥 전환)에서
  양쪽 앱이 모두 식별되고 bundleId가 서로 다른 경우다.
- FR-8: 같은 앱 안의 창·탭·URL 변경, 수집 공백이나 60초 초과 침묵을 사이에 둔
  앱 변화, 어느 한쪽이 `앱 미확인`이거나 불투명 활동인 전환은 세지 않는다.
- FR-9: 전환 시각은 새 구간의 시작 시각이다. 날짜별 횟수는 전환 시각이 속한
  타임라인 날짜로, 세션별 횟수는 전환 시각이 세션의 작업 시간(시작~종료에서
  일시중지 구간 제외)에 속할 때 센다.
- FR-10: 각 전환은 이전 앱, 다음 앱, 전환 시각, 이전 앱의 머문 시간을 제공한다.
  짧은 체류 전환을 걸러내는 최소 시간은 두지 않는다.

### 집중 이탈과 방해 앱

- FR-11: 분석 대상은 완료된 집중 세션이다. 세션의 분석 시간은 시작~종료에서
  일시중지 구간을 뺀 시간이며, 세션 시간과 겹치는 관찰 활동 구간은 겹친 부분만
  사용한다.
- FR-12: 분석 시간의 각 구간을 다음 중 하나로 판정한다.
  - **집중 활동**: 확정 라벨이 세션 라벨과 같다.
  - **이탈 활동**: 확정 라벨이 세션 라벨과 다르다.
  - **확정 미분류**: 미분류로 확정됐다. 이탈로 보지 않는다.
  - **판정 대기**: 라벨이 아직 확정되지 않았다.
  - **불투명 활동**: 라벨 대상이 아니므로 판정하지 않는다.
- FR-13: 세션별로 위 판정의 시간 합계와, 관찰되지 않은 시간(수집 공백·침묵)을
  분리해 제공한다.
- FR-14: 집중 이탈은 이탈 활동이 시작된 시점부터 집중 활동으로 돌아오거나 세션
  분석 시간이 끝날 때까지 이어진 이탈 활동의 묶음이다. 확정 미분류·판정 대기·
  불투명 활동·미관찰 시간·일시중지 구간은 집중 이탈을 끝내지 않지만 이탈 시간에
  포함하지도 않는다.
- FR-15: 방해 앱은 집중 이탈을 시작한 첫 이탈 활동의 앱이다. 집중 이탈 안에서
  사용한 앱별 이탈 시간도 함께 제공한다.
- FR-16: 세션별로 방해 앱 목록(앱별 이탈 횟수·이탈 시간)을 제공한다.

### 이탈 근거

- FR-17: 각 집중 이탈에 다음 관찰 근거를 제공한다.
  - 진입 구간의 앱·창 제목·URL과 확정 라벨(원본 문맥 그대로, 의미 정규화 없음).
  - 직전 집중 활동의 앱.
  - 세션 시작 후 경과한 작업 시간.
  - 이탈 시간과 이탈 안의 컨텍스트 스위칭 횟수.
  - 집중 활동으로 복귀했는지 여부.
- FR-18: 알림·피로 같은 동기는 추정하지 않는다.

### 일시중지 구간

- FR-19: 집중 세션 완료 요청은 선택적으로 일시중지 구간 목록 `[시작, 종료)`를
  받는다. 기존 클라이언트처럼 목록이 없으면 일시중지 정보가 없는 세션으로 저장한다.
- FR-20: 일시중지 정보가 없는 세션은 시작~종료 전체를 분석 시간으로 사용하고,
  분석 결과에 일시중지 정보가 없었음을 표시한다.

### 갱신

- FR-21: 라벨 확정·정정, 늦게 도착한 관찰과 그에 따른 관찰 구간 재구성은 다음
  분석 조회부터 반영된다. 과거 분석 결과를 별도로 고정하지 않는다.

## 정책과 불변식

- 분석은 관찰 타임라인·확정 라벨·집중 세션을 읽기만 하며 원천 데이터를 바꾸지 않는다.
- 이탈 판정에는 사용자 확정 라벨만 쓴다. 라벨 제안은 판정 대기로만 반영한다.
- 수집 공백과 관찰 침묵을 활동·전환·이탈로 추정하지 않는다.
- 불투명 활동은 앱·문맥 정보를 어떤 분석 결과에도 노출하거나 귀속하지 않는다.
- 일시중지 구간의 시간은 세션 분석 시간, 세션별 전환, 집중 이탈에서 제외한다.
- 계정의 분석은 그 계정의 데이터만 사용한다.

## 예외와 경계 조건

- 0초 관찰 구간도 전환의 이전·다음 구간이 될 수 있다. A→B(0초)→C는 전환 2회다.
- 같은 앱으로 돌아오는 A→B→A는 전환 2회다.
- 세션 시작 직전부터 이어진 구간은 세션 시작 시각부터의 겹친 부분만 판정한다.
- 자정을 넘는 세션은 집중 세션 계약대로 시작 날짜에 속한다. 세션 분석은 날짜와
  무관하게 세션 시간 전체를 사용한다.
- 세션 라벨이 이후 보관되어도 세션 라벨 기준 판정은 유지한다.
- 일시중지 구간은 세션 시작~종료 안에 있어야 하고 서로 겹치지 않아야 하며, 위반
  시 완료 요청을 거절한다. `workSeconds`와의 정합 검증 방식은 미결정이다.
- 완료 후 늦게 도착한 유효한 관찰은 다음 조회의 분석에 반영된다.
- 진행 중 세션은 분석하지 않는다.

## 비기능 요구사항

- 같은 원천 데이터에 대한 분석 결과는 조회 순서·전송 순서와 무관하게 결정적이다.
- 공개 계약은 Pydantic 모델·camelCase·공통 오류 응답을 따르고 OpenAPI를 갱신한다.
- 수치 성능 목표는 정하지 않았다.

## 확장 방향

다음은 현재 범위가 아니지만 기존 결과의 의미를 바꾸지 않고 추가할 수 있어야 한다.

- 분석 차원: 앱 외에 브라우저 도메인을 사용·전환의 식별 단위로 추가.
- 전환 판정: 확정 라벨 전환 지표, 최소 체류 시간 필터.
- 기간: 날짜 외 주·임의 기간, 시간대별 분포.
- 이탈 원인: 사용자 사유 입력, 세션별 허용 앱 지정.

## 제외 범위

- AI에 의한 이탈 판정·원인 추정.
- 사용자 사유 입력, 세션별 허용 앱 목록.
- 진행 중 세션의 실시간 분석과 이탈 알림.
- 집중도 점수 같은 합성 지표.
- 도메인·URL 단위 사용 시간과 전환.
- 여러 활성 Device의 겹치는 기록 해결(관찰 타임라인의 단일 순서를 그대로 따른다).
- macOS 화면 구현.

## 인수 조건

- AC-8001: Given 한 날짜에 앱 A 30분, B 10분, 불투명 활동 5분, bundleId 미확인
  2분이 관찰됨 When 날짜별 앱 사용 시간을 조회 Then A, B 순서로 앱 시간을 받고
  불투명·미확인·전체 관찰 시간을 별도 값으로 받는다.
- AC-8002: Given 자정을 넘는 구간과 열린 구간 When 날짜별 앱 사용 시간을 조회
  Then 날짜와 겹친 시간만, 열린 구간은 `lastObservedAt`까지만 합산한다.
- AC-8003: Given 수집 공백과 60초 초과 침묵 When 앱 사용 시간을 조회 Then 그
  시간은 어떤 값에도 포함되지 않는다.
- AC-8004: Given 맞닿은 구간 A→A(다른 탭)→B→A When 컨텍스트 스위칭을 조회 Then
  2회이며 각 전환의 이전·다음 앱, 시각, 머문 시간을 받는다.
- AC-8005: Given 수집 공백·60초 초과 침묵·불투명 활동·앱 미확인 구간을 사이에 둔
  앱 변화 When 조회 Then 전환으로 세지 않는다.
- AC-8006: Given 같은 시각의 0초 구간을 포함한 A→B→C When 조회 Then 2회다.
- AC-8007: Given 세션 라벨이 `코딩`이고 세션 중 `코딩`·`여가`·확정 미분류·미확정·
  불투명 구간이 있음 When 세션 분석을 조회 Then 각각 집중·이탈·확정 미분류·판정
  대기·불투명 시간으로 분리되고 미관찰 시간도 별도로 받는다.
- AC-8008: Given 코딩→여가(앱 B)→판정 대기→여가(앱 C)→코딩 When 세션 분석을 조회
  Then 집중 이탈 1건이고 방해 앱은 B이며 앱별 이탈 시간에 B와 C가 있고 판정 대기
  시간은 이탈 시간에 포함되지 않는다.
- AC-8009: Given 집중 이탈 When 조회 Then 진입 구간의 앱·창 제목·URL·확정 라벨,
  직전 집중 활동의 앱, 세션 시작 후 경과 작업 시간, 이탈 시간, 이탈 안의 전환
  횟수, 복귀 여부를 받는다. 불투명 활동의 정보는 노출되지 않는다.
- AC-8010: Given 일시중지 구간을 포함해 완료한 세션 When 세션 분석을 조회 Then
  일시중지 중 구간·전환은 판정·횟수에서 제외된다.
- AC-8011: Given 일시중지 구간 없이 완료한 기존 클라이언트 세션 When 조회 Then
  시작~종료 전체를 분석하고 일시중지 정보 없음이 표시된다.
- AC-8012: Given 세션 밖이거나 서로 겹치는 일시중지 구간 When 완료를 요청 Then
  기존 오류 계약으로 거절된다.
- AC-8013: Given 분석에 쓰인 구간의 라벨을 정정하거나 늦은 관찰이 도착 When 다시
  조회 Then 최신 확정과 관찰 사실로 결과가 바뀐다.
- AC-8014: Given 다른 계정의 데이터 When 분석을 조회 Then 섞이지 않고, 진행 중
  세션은 분석 대상이 아니다.

## 확인된 사실·가정·미결정

### 확인된 사실

- 관찰 활동 구간의 context에는 앱 bundleId·이름, 창 제목, 브라우저 탭 제목·URL이
  필드별 수집 상태와 함께 있다. 불투명 활동은 식별 정보가 없다.
- 기존 용어집은 `컨텍스트 스위칭`을 `관찰 문맥 전환`의 동의어로 쓰지 않으며,
  관찰 타임라인·라벨링 PRD는 컨텍스트 스위칭·집중도 판단을 비목표로 두었다.
- 집중 세션은 라벨 하나와 `workSeconds` 합계만 저장하며 일시중지 구간은 저장하지
  않는다. 일시중지 중 관찰은 세션에 연결하지 않는다.
- 라벨 대시보드는 확정값만 합산하고 날짜 경계를 넘는 구간은 겹친 시간만 합산한다.

### 사용자 결정 (2026-10-25)

- 컨텍스트 스위칭 단위는 앱(bundleId) 전환이다.
- 이탈 판정은 세션 라벨과 다른 확정 라벨이며 미확정은 판정 대기로 분리한다.
- 이탈 원인은 관찰 근거만 제공한다.
- 일시중지 구간을 완료 요청으로 받아 저장하고 분석에서 제외한다.

### 가정 (추천안, 검토 필요)

- 열린 구간은 앱 사용 시간에 `lastObservedAt`까지 포함한다. 라벨 대시보드는 열린
  구간을 제외하지만, 앱 사용 시간은 관찰 사실 집계이므로 근거가 있는 시간까지
  포함하는 편이 수 시간짜리 진행 중 구간 누락을 막는다. 제외하면 라벨 집계와
  일관되지만 오늘 화면의 수치가 크게 늦어진다.
- 확정 미분류는 이탈이 아니다. 이탈로 보면 "확인했지만 분류하지 않은" 활동이
  방해로 집계되어 미분류 확정을 꺼리게 만든다.
- 불투명 활동·앱 미확인 구간이 낀 앱 변화는 전환으로 세지 않는다. 불투명 활동은
  같은 앱일 수도 있어 세면 과대 집계되고, 세지 않으면 일부 실제 전환이 누락된다.
- 방해 앱은 집중 이탈의 진입 앱이다. 이탈 안의 모든 앱을 방해 앱으로 보면 연쇄
  이동한 앱까지 원인처럼 보인다.

### 미결정

- 일시중지 구간 합계와 `workSeconds`의 정합 검증(엄격 일치, 허용 오차, 검증 없음).
  추천: 초 단위 내림 오차만 허용. 엔지니어링 계획에서 기존 클라이언트 값으로 확인한다.
- 분석의 공개 API 경로·응답 형태와 저장 방식은 엔지니어링 계획에서 정한다.
