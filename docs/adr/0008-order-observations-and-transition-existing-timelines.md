# Device별 관찰 순번으로 타임라인을 구성하고 기존 이력을 전환한다

## 맥락

배치 전송에서는 순번 누락과 낮은 sequence의 지연 도착을 허용한다. 수신 순서가
달라도 같은 원본 집합의 관찰 의미가 같아야 한다. 여러 Device의 sequence는
독립적이므로 계정 전역 순번으로 비교할 수 없다.

ADR 0004는 원본을 `(observedAt, receivedAt, eventId)` 순으로 해석했다. 이 방식은
같은 시각의 관찰이 전송·수신 순서에 영향을 받는다. 새 정렬 기준을 적용하면
과거의 동률 기록 순서와 타임라인 경계·내용 버전·라벨 적용성이 달라질 수 있다.
새 입력 근처만 재구성해서는 기존 이력 전체가 새 기준을 따른다고 보장할 수 없다.

선택 기준은 Device 내 관찰 순서 보존, 전송 순서에 독립적인 결과, 비음수 구간,
기존 원본 보존, 초기 전환의 원자성과 정상 처리의 재계산 비용이다.

## 결정

### 원본 순서와 시각

- 같은 Device 내 관찰 순서는 `sequence ASC`다. 연속된 숫자를 요구하지 않으며
  미사용 낮은 sequence가 늦게 도착해도 수용한다. 순번 누락만으로 공백을 만들지 않는다.
- 같은 Device에서 sequence가 증가할 때 observedAt은 같거나 증가해야 한다.
  역행하면 해당 배치의 DB 변경 전체를 롤백한다. 실패 원본 보관·복구는 후속 범위다.
  원본 시각을 보정하거나 음수 간격을 정상 병합하거나 거짓 경계를 만들지 않는다.
- 여러 Device의 원본은 `(observedAt, deviceId, sequence, eventId)` 오름차순으로
  병합한다. receivedAt은 원본 순서 결정에 사용하지 않는다.
- 다른 Device의 sequence를 직접 비교하지 않는다. 관찰 시각이 같으면 Device
  식별자로 순서를 결정하고, 같은 Device 내에서는 sequence로 순서를 결정한다.
- Device 변경은 문맥 grouping 경계가 아니다. 기존 문맥 동등성·60초 병합·명시적
  수집 공백·길이 없는 구간·날짜 경계·내용 버전·라벨 적용성 규칙을 유지한다.
- 같은 시작 시각의 응답 구간도 해당 구간의 시작 원본이 가진 새 정렬 순서를 따른다.

### 정상 배치 처리

- append는 마지막 구간 상태와 새로 채택한 원본에서 증분 계산한다.
- 과거 변경은 배치 단위로 묶고 영향을 받는 기존 구간의 시작부터 재생한다.
  모든 신규 원본을 지난 뒤 기존 닫힌 구간의 전체 계산 상태와 일치하는 안전한
  경계에서 중단한다. 매 배치 계정 전체 재생을 정상 경로로 삼지 않는다.
- 결과는 같은 원본 집합의 전체 재생과 관찰 의미가 같아야 한다. 이 비교에서는
  영구 도메인 식별자가 아닌 projection ID를 구분한다.

### 기존 이력의 최초 전환

- 현재 전환 방식은 계정의 첫 receipt 처리 트랜잭션에서 기존 원본의 Device별
  관찰 시각 비감소를 확인하고, 기존 이력이 있으면 새 정렬 기준으로 전체를
  한 번 재구축하는 것이다. 중복 원본만 들어온 첫 배치도 전환을 수행한다.
- 전환은 원본을 다시 쓰지 않는다. 기존 구간 ID의 재사용과 내용 버전·라벨
  적용성 계산은 기존 규칙을 유지한다.
- 전환·새 배치 반영·receipt 저장은 같은 계정 잠금과 DB 트랜잭션에서 처리한다.
  실패하면 함께 롤백하고 다음 처리에서 다시 시도한다. 전환 후 배치는 정상
  증분·부분 재구성 경로를 사용한다.
- 최초 전체 재구축은 부분 재구성으로 최적화할 필요가 있다. 최적화는 후속 작업으로
  남기고 완료 전까지 현재 최초 전환 방식을 유지한다.
- 부분 전환은 기존·새 정렬의 차이가 발생하는 지점을 먼저 식별해야 한다.
  최초 영향 구간부터 마지막 변경 지점을 지난 안전한 수렴 경계까지 계산한다.
  중간 구간이 같다는 이유만으로 이후 모든 구간을 재사용하지 않는다.

## 고려한 대안

### 원본 순서

| 대안 | 장점 | 비용·제약 | 선택 |
| --- | --- | --- | --- |
| observedAt·receivedAt·eventId 유지 | 기존 정렬·이력을 유지할 수 있다. | 동일 시각의 관찰 의미가 전송·수신 순서에 영향을 받는다. | 대체 대상 |
| 모든 Device의 sequence를 전역 비교 | 정렬식이 단순하다. | 서로 독립된 Device의 순번에 계정 전체의 시간 순서를 부여하게 된다. | 미채택 |
| Device별 sequence와 비감소 시각을 전제로 여러 Device를 결정적으로 병합 | Device 내 순서와 전송 순서 독립성을 함께 유지한다. | 시각 역행 배치의 실패 처리와 기존 이력 전환이 필요하다. | 채택안 |

### 기존 이력 전환

| 대안 | 장점 | 비용·제약 | 선택 |
| --- | --- | --- | --- |
| 새 입력 근처만 재계산 | 최초 처리량이 작다. | 새 입력과 무관한 과거 동률 기록을 놓치며, 중간 수렴만으로 이후 이력의 정합성을 보장할 수 없다. | 미채택 |
| 첫 배치 트랜잭션에서 전체 재구축 | 계정 이력을 새 기준으로 전환하고 실패 시 원자적으로 되돌릴 수 있다. | 최초 계산·원본 조회·잠금 유지 비용이 계정 이력에 비례한다. | 현재 전환 방식 |
| 변경 지점 탐색 후 영향 범위만 재구성 | 영향 없는 구간의 재계산과 재저장을 줄일 수 있다. | 변경 지점 탐색과 재구성 경계의 정확성을 별도로 보장해야 한다. | 필요한 후속 최적화 |
| 별도 migration에서 전체 재구축 | 전환을 배포 단계에 명시적으로 수행할 수 있다. | 이력 크기에 따른 배포 비용과 진행·실패·재실행 계획이 필요하다. | 비교 대안 |

## 결과와 트레이드오프

- 같은 Device의 시계가 뒤로 움직이면 유효한 나머지 원본도 해당 배치에서는
  반영되지 않는다. 실패 원본 보관·후속 보류·재처리는 배치 처리 계약의 후속 요구로 유지하며 이번 완료 조건에서 제외한다.
- Device 식별자 동률 규칙은 실제 동시 관찰의 선후를 알아냈다는 의미가 아니라,
  같은 원본 집합에 대해 결정적인 결과를 만드는 규칙이다.
- 초기 전환에서는 서로 떨어진 여러 시각의 동률 순서가 바뀔 수 있다. 앞부분
  재계산 결과가 같아도 뒤에 또 다른 변경 지점이 있을 수 있다.
- 최적화 검증에는 떨어진 복수 동률 구간, 여러 Device, 중간 수렴 이후의 추가
  변경, 중복 전용 첫 배치, 지연·append 첫 배치와 전환 실패 후 재시도를 포함한다.
  최적화 결과는 전체 재생과 같은 관찰 의미·라벨 적용성을 유지해야 한다.
- 변경 지점 탐색 비용과 실제 원본 재생·구간 교체 비용은 구분한다. 부분 재구성이
  가능하더라도 이력 조사 비용이 없어지거나 처리량이 개선됐다고 측정 없이 주장하지 않는다.
- 현재 receipt 존재에 연결된 전환 완료 판별은 receipt retention과 결합돼 있다.
  후속 최적화·보존 정책 설계에서 전환 완료의 판별 방식도 함께 검토한다.

## 대체한 ADR

[ADR 0004](0004-project-observation-timeline-on-write.md)의 원본 순서와 기존
이력 전환 관련 결정을 부분 대체한다(supersedes in part).

- receivedAt 동률 정렬을 새 Device별 관찰 순서와 결정적 병합으로 대체한다.
- Device별 sequence를 유일성 판정에만 쓰던 규칙을 관찰 순서에도 사용하도록 바꾼다.
- 이번 정렬 전환은 첫 배치 트랜잭션에서 수행하며 부분 재구성 최적화를 후속
  과제로 둔다. 모든 향후 grouping 변경을 같은 방식으로 전환한다고 일반화하지 않는다.

원본·projection 원자성, 계정 잠금, 날짜 경계, Device 출처 비노출과 GET에서
원본을 재생하지 않는 결정은 유지한다. 배치 receipt와 비동기 쓰기 경계는 ADR 0007을 따른다.
