# 활동 원본은 유지하고 관찰 타임라인은 쓰기 시 projection한다

Mosemo는 `activity_records`를 유일한 활동 원본으로 유지하면서, 반복되는 날짜별
관찰 타임라인 grouping을 `activity_timeline_segments` 읽기 모델에 저장한다. 활동
POST가 원본과 projection을 같은 트랜잭션에서 갱신하고 GET은 projection을 읽는다.
조회 시마다 원본에서 계산하는 ADR 0002의 결정을 이 ADR이 대체한다.

## 결정

- 계정의 모든 Device가 만든 활동 레코드는
  `(observed_at, received_at, event_id)` 순서로 하나의 스트림처럼 해석한다. Device
  경계와 Device별 `sequence`는 관찰 타임라인의 grouping 또는 표시 경계가 아니다.
- 관찰 활동 구간과 수집 공백은 하나의 `activity_timeline_segments` 테이블에
  discriminated union 형태로 저장한다. 각 행은 UUIDv7 projection 식별자와 구간을
  시작한 원본 이벤트를 참조한다. 활동 구간은 마지막 동일 문맥 관찰 이벤트도
  참조한다.
- 원본 삽입, 중복·충돌 판정, 오래된 열린 구간의 물리적 종료와 projection 갱신은
  하나의 쓰기 트랜잭션에 포함한다. 실패하면 원본 삽입도 함께 롤백한다.
- 같은 계정의 쓰기는 `activity_timeline:{account_id}`를 BLAKE2b 64비트로 변환한
  PostgreSQL transaction-level advisory lock으로 직렬화한다. 락 대기는 3초로
  제한하고, 초과하면 전체 트랜잭션을 롤백한 뒤 재시도 가능한 공개 503 오류를
  반환한다. 서로 다른 계정의 쓰기는 병렬로 처리한다.
- 늦거나 순서가 뒤바뀐 원본도 수락한다. 새 이벤트가 영향을 주는 기존 구간부터
  원본을 다시 재생하고, 새 결과가 기존 다음 구간과 수렴할 때까지 범위를 앞으로
  확장한다. 고정 개수의 이웃 구간이나 계정 전체 재계산을 정상 경로로 삼지 않는다.
- 조회는 projection을 원본에서 다시 계산하거나 자동 복구하지 않는다. grouping
  규칙이 바뀌면 새 migration에서 보존된 원본으로 전체 projection을 재구축하며,
  별도 projection 버전 컬럼이나 상태 테이블은 두지 않는다.
- 타임라인 날짜 경계는 계정의 IANA 시간대로 계산한다. 구간은 날짜 경계에서
  자르지 않고, 응답에는 Device 출처나 projection의 원본 이벤트 식별자를 노출하지
  않는다.

## 고려한 대안

- ADR 0002의 조회 시 계산은 쓰기 모델이 단순하지만 같은 grouping을 반복하고,
  날짜 조회마다 경계 이전 원본을 다시 읽어야 하므로 선택하지 않았다.
- 낙관적 락과 재시도는 충돌 시 계산을 반복하고 최종 성공 순서를 보장하기 위한
  별도 버전 상태가 필요하므로, 반드시 순차 처리해야 하는 계정별 projection에는
  선택하지 않았다.
- `accounts` 행 잠금은 활동 처리량을 계정의 다른 변경과 불필요하게 결합하므로
  선택하지 않았다.
- 활동 구간과 수집 공백을 별도 테이블로 나누면 공통 시간순 조회와 식별자 정책이
  중복되므로 선택하지 않았다.
- scheduler로 오래된 열린 구간을 닫는 방식은 배경 실행 상태를 추가하므로 선택하지
  않았다. GET은 현재 시각에 따라 응답에서 논리적으로 닫고 다음 쓰기가 이를
  projection에 반영한다.

## 결과

- 날짜별 GET은 저장된 읽기 모델을 조회하지만, 쓰기 경로는 grouping과 동시성
  제어를 함께 책임지므로 복잡해진다.
- advisory lock의 64비트 해시가 충돌하면 무관한 두 계정이 일시적으로 직렬화될 수
  있으나 데이터가 섞이거나 잘못 갱신되지는 않는다.
- projection 식별자는 단순 연장이나 종료에는 유지되지만 병합, 분할, 전체 재구축
  과정에서는 바뀔 수 있으므로 영구 도메인 식별자로 사용할 수 없다.
- 현재는 한 계정에 하나의 활성 기록 Device만 있다는 제품 전제를 사용한다. 인증
  계층에서 이 전제를 강제하는 작업은 이 결정의 범위 밖이다.
