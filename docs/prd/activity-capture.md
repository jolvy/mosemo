# 활동 관찰과 개인정보 보호 PRD

## 문제와 배경

사용자는 현재 포커스한 활동을 기록하면서 저장하면 안 되는 식별 정보가 서버로
전송되지 않기를 원한다. 활동을 관찰했지만 개인정보를 제거한 경우, 관찰 대상이
없는 경우, 값을 읽지 못한 경우와 수집 자체가 중단된 경우를 구별해야 한다.

## 목표와 비목표

### 목표

- 현재 포커스한 대상의 전체 관찰값을 활동 레코드로 만든다.
- 식별 정보는 서버 전송 전에 클라이언트에서 필터링한다.
- 앱·창·웹의 관찰 상태를 독립적으로 표현한다.
- 개인정보로 제거한 값, 길이 제한으로 보관하지 않은 URL과 절삭한 제목을 구별한다.

### 비목표

- 모든 창·백그라운드 앱의 목록 수집.
- 클라이언트의 활동 구간 계산, 문맥의 의미상 병합, AI 해석·라벨 확정.
- 브라우저별 수집 구현·권한 획득 UI의 구체 방식.
- 배치 전송·재시도·Kafka 처리 및 타임라인 구간 계산의 중복 정의.

## 사용자와 사용자 시나리오

- 사용자는 현재 작업 중인 앱·포커스 창·브라우저 탭의 활동을 기록한다.
- 개인정보를 남기면 안 되는 활동은 식별 정보 없이 정상 관찰 사실만 기록한다.
- 창이 없거나 특정 필드를 읽지 못해도, 다른 필드에서 관찰한 사실은 유지한다.
- 잠금·절전·사용자 중지·접근 권한 상실로 수집할 수 없으면 수집 상태 변경을 기록한다.

## 현재 구현 범위

macOS 클라이언트의 포커스 대상 관찰, 전체 스냅샷 생성, 전송 전 개인정보
필터링과 활동 레코드의 관찰 상태 표현을 정의한다. 전체 스냅샷은 이전 값과의
차이가 아니라 해당 시점에 알 수 있는 전체 관찰값이다.

클라이언트는 관찰 원본을 만들며 활동 구간으로 합치지 않는다. 전송·수락·재시도는
[활동 배치 PRD](activity-batches.md), 서버의 구간 계산·조회는
[관찰 타임라인 PRD](observation-timeline.md)를 따른다.

## 기능 요구사항

### 관찰 대상과 시점

현재 포커싱된 앱과 그 포커스 창만 관찰한다. 브라우저 문맥은 포커싱된 대상의
탭 제목과 URL을 관찰하며 다른 창·백그라운드 앱을 나열하지 않는다.

다음 시점에는 새로운 전체 스냅샷을 만든다.

- 수집 시작 또는 중단 후 재개.
- 포커싱된 앱 변경.
- 포커스 창·창 제목·브라우저 탭·URL 변경.
- 수집 가능성 변경 이후 다시 관찰할 수 있게 된 시점.
- 변화가 없어도 활성 수집 중 마지막 관찰 후 30초가 지난 시점.

이 주기는 관찰 원본 생성 조건이며 배치 전송 대기 시간이나 타임라인의 60초
병합 경계와는 별개다.

### 전체 관찰 문맥과 필드 상태

`activity_observation`은 개인정보 필터를 적용한 전체 스냅샷을 담는다. 앱·창·웹과
그 안의 필드는 각각의 관찰 상태를 표현하며, 한 필드의 실패를 다른 필드의
부재나 실패로 확대하지 않는다.

| 대상 | 표현 |
| --- | --- |
| 앱 bundleId·표시 이름 | 각각 captured·absent·unavailable과 필요한 값·사유 |
| 포커스 창 | captured·absent·unavailable. captured인 경우 제목 포함 |
| 웹 문맥 | not_applicable 또는 browser |
| 브라우저 탭 제목·URL | 각각 captured·absent·unavailable·redacted와 필요한 값·사유 |

`absent`는 대상 값이 없다는 뜻이며, `unavailable`은 읽지 못했다는 뜻이다.
`redacted`에는 값을 저장하지 않은 개인정보 정책상의 사유를 담는다.

### 개인정보 필터와 길이 제한

식별 정보는 서버에 보내기 전에 클라이언트에서 제거한다.

| 상황 | 전송 값 |
| --- | --- |
| 개인정보를 저장하면 안 되는 활동 | context는 kind: opaque만 포함 |
| data: 또는 javascript: URL | URL은 redacted, reason은 embedded_content_scheme |
| 허용 길이를 넘는 URL | URL은 redacted, reason은 length_exceeded |
| 창 제목을 읽지 못함 | 창은 unavailable과 수집 실패 사유 |
| 창 자체가 없음 | 창은 absent |

불투명 활동은 개인정보 필터가 적용된 정상 관찰이다. 앱·창 제목·도메인·해시·필터
규칙 이름 등 식별 가능한 정보를 덧붙이지 않으며 수집 공백으로 취급하지 않는다.

창·탭 제목이 길이 제한을 넘으면 원문 앞부분과 `truncated: true`, 절삭 전 원문의
UTF-8 바이트 길이인 `originalByteLength`를 함께 전송한다. URL은 일부를 잘라
전송하지 않는다. 비식별화 대상이 아닌 URL은 관찰한 문자열 그대로 보존한다.
서버가 정규화하거나 query·fragment를 제거하지 않으며, URL을 파싱할 수 없다는
이유만으로 관찰을 거절하지 않는다.

### 수집 상태 변경

잠금·절전·사용자 중지·접근 권한 상실처럼 관찰할 수 없는 상태는
`collection_state_changed` 원본으로 보낸다. state는 active 또는 suspended이며
reason은 수집 가능성에 대한 사유로 사용하고 사용자 활동 내용을 담지 않는다.

수집이 재개되면 전체 스냅샷을 다시 만든다. active 알림과 실제 활동 관찰은
구별하며 공백 종료·구간 생성의 의미는 관찰 타임라인 PRD를 따른다.

## 정책·제약·엣지케이스

- 전체 스냅샷이 이전 관찰값의 차이만 포함하거나 이전 요청의 필드 상태에 의존하지 않는다.
- 앱·창·웹 필드의 수집 실패를 모두 불투명 활동으로 바꾸지 않는다. 불투명 활동은
  식별 정보를 남기지 않기로 한 정상 관찰이다.
- 비식별화한 필드는 원문을 함께 보내지 않고, 수집 실패·개인정보 사유에도
  식별 가능한 활동 내용을 넣지 않는다.
- 제목의 길이 절삭과 URL 비식별화는 다른 결과다. URL에 제목 절삭 규칙을 적용하지 않는다.
- 서버 전송 이후에만 필터링하는 방식으로 개인정보 보호 책임을 옮기지 않는다.
- 수집 간격·전송 간격·구간 병합 조건을 각각의 계약대로 적용한다.

## 비기능 요구사항

개인정보 보호 처리는 서버 전송 전에 완료한다. 관찰한 값과 읽지 못한 상태를
구분하고 문맥을 의미상 정규화하지 않는다. 식별 정보를 제외한 원본 사실과 이후
AI 제안·사용자 확정은 분리한다. 관찰 변경 감지의 수치 지연 목표는 별도로 정하지 않는다.

## 확장 방향

관찰 레코드와 필드 상태의 의미를 유지하면서 지원 브라우저·관찰 방식을 확장할 수
있어야 한다. 새로운 관찰 수단이 같은 개인정보 필터와 전송 전 제거 경계를 따르도록 한다.

## 인수 조건

- AC-7001: 앱·창이 여러 개 열려 있어도 현재 포커스한 앱·창만 관찰하며,
  브라우저 문맥은 해당 포커스 대상에서 수집한다. 백그라운드 앱·전체 창 목록은 수집하지 않는다.
- AC-7002: 수집 시작·재개, 앱·창·제목·탭·URL 변경 시 전체 스냅샷을 만들고,
  활성 수집 중 변화가 없어도 마지막 관찰 후 30초가 지나면 새 스냅샷을 만든다.
- AC-7003: 스냅샷은 이전 요청을 참조하지 않아도 그 시점의 앱·창·웹 관찰 상태를
  해석할 수 있다. 한 필드의 수집 실패가 다른 필드의 관찰값을 제거하지 않는다.
- AC-7004: 창 자체가 없으면 absent, 창을 읽지 못하면 unavailable과 실패 사유를
  전송한다. 값 부재와 수집 실패를 같은 상태로 표현하지 않는다.
- AC-7005: 개인정보를 남기면 안 되는 활동은 전송 전에 식별 정보를 제거해
  kind: opaque만 전송하고 앱·제목·도메인·해시·필터 규칙 이름을 덧붙이지 않는다.
- AC-7006: data:·javascript: URL은 원문 없이 redacted와 embedded_content_scheme을,
  허용 길이 초과 URL은 원문 없이 redacted와 length_exceeded를 전송한다.
- AC-7007: 제목이 길이 제한을 넘으면 원문 앞부분, truncated: true와 원래 UTF-8
  바이트 길이를 함께 보낸다. URL에는 이 절삭 방식을 적용하지 않는다.
- AC-7008: 허용된 URL은 관찰한 문자열을 그대로 유지하며, 서버가 query·fragment를
  제거하거나 파싱 실패만을 이유로 원본을 거절하지 않는다.
- AC-7009: 잠금·절전·사용자 중지·권한 상실은 수집 상태 변경 원본으로 표현하고
  사유에 사용자 활동 내용을 넣지 않는다. 재개 시 실제 활동 스냅샷을 새로 만든다.
- AC-7010: 불투명 활동과 수집 공백을 구분하고, 클라이언트에서 문맥을 의미상
  병합하거나 타임라인 구간을 생성하지 않는다.

## 미결정 사항과 가정

제목·URL의 구체적인 바이트 상한은 이 명세에서 수치를 정하지 않는다. 배치의
512 KiB 본문 한도를 개별 필드의 상한으로 사용하지 않는다. 지원 브라우저와
권한·수집 수단의 세부 구현은 별도 범위다.
