# 활동 분석 지표 명세 (C1~C7)

[활동 분석 요구사항](requirements/activity-analytics.md)의 C1~C7을 정의·단위·포함·제외·경계 사례·반례로
고정한다. 경계 사례(`B`)와 반례(`X`)의 ID는 실행 가능한 기대값과 1:1로 대응하며, 참조 구현
단계에서 테스트 ID로 옮긴다. 반례는 "그럴듯한 다른 정의가 다른 값을 내는 입력"이며 이 명세가
그 정의를 택하지 않은 이유를 함께 적는다.

공통 표기:

- 구간 `[m0, m1)`은 분 단위 시각이다. 별도 표기가 없으면 앞 구간의 끝과 뒤 구간의 시작이 같은
  **맞닿은** 구간이다.
- **침묵**은 마지막 관찰 후 60초를 넘겨 다음 관찰이 온 경우다. 앞 구간의 끝은 마지막 관찰
  시각이고 뒤 구간과 맞닿지 않는다.
- **유효한 확정**은 확정 당시 `segment_version`이 현재 구간 version과 같은 확정이다.
- 세션 예시는 `[0, 60)`, 세션 라벨 `코딩`이다.

## C1 앱·사이트 사용 시간

**사용자에게**: 그날 각 앱(사이트)이 화면 맨 앞에 있었다고 관찰된 시간이며, 관찰이 끊긴 시간은
어떤 앱에도 넣지 않는다.

| 항목 | 내용 |
| --- | --- |
| 정의 | 날짜와 겹치는 관찰 활동 구간의 겹친 시간을 앱별·사용 대상별로 합한다. |
| 단위 | 초. 계정 시간대 날짜 단위. 지난 날짜는 일간 통계로 저장하고 오늘은 조회 때 계산한다. |
| 포함 | 상세 문맥 활동 구간. 열린 구간은 `lastObservedAt`까지. 앱 미확인·불투명은 별도 값과 전체 관찰 시간에. |
| 제외 | 수집 공백, 60초 초과 침묵, 열린 구간의 `lastObservedAt` 이후. |
| 사용 대상 | 브라우저(`web.kind = browser`)이고 URL이 `captured`면 사이트(eTLD+1), URL이 없으면 브라우저 앱, 그 밖은 앱. 브라우저 여부는 클라이언트가 보낸 `web.kind`로만 판정한다. `http`·`https` URL인데 eTLD+1을 정할 수 없으면 호스트 그대로(포트 제외)가 사이트이고, `http`·`https`가 아니거나 호스트가 없는 URL은 브라우저 앱이다(D7). scheme 바로 뒤에 `://`가 없으면 `^[a-z][a-z0-9+.-]*:` 뒤 첫 글자가 숫자가 아닐 때(`about:blank`, `javascript:`, `data:`) 브라우저 앱이고, 그 밖(`meet.google.com/x`, `localhost:8000/docs`, `example.com/?r=https://a.com`)은 `https://`를 붙여 D7을 적용한다. scheme은 대소문자를 가리지 않는다. 원본 URL은 바꾸지 않는다(D9). 사이트의 비교·저장 키는 IDNA 2003(nameprep)으로 바꾼 ASCII 소문자이며, 끝의 점은 모두 지운다. 화면에는 유니코드로 바꿔 보여 준다(D12). |

## C2 날짜별 사용 대상 전환

**사용자에게**: 그날 하던 것을 끊김 없이 다른 앱이나 사이트로 바꾼 횟수이며, 관찰이 끊긴 사이의
변화는 세지 않는다.

| 항목 | 내용 |
| --- | --- |
| 정의 | 맞닿은 두 활동 구간의 사용 대상이 모두 식별되고 서로 다르면 1회. 전환 시각은 뒤 구간의 시작. |
| 단위 | 횟수(목록 행 수). 각 행: 전환 시각, 이전·다음 대상, 이전 대상 체류 시간(초). |
| 체류 시간 | 전환 직전까지 이전 사용 대상으로 맞닿아 이어진 구간들의 길이 합. 공백·침묵·다른 사용 대상(불투명·앱 미확인 포함)에서 끊기며 날짜 경계와 무관하다(자정 너머까지 이어진다). |
| 포함 | 0초 구간을 앞뒤로 둔 전환, 짧은 왕복(최소 체류 없음). |
| 제외 | 같은 사용 대상 안의 창·탭·URL 변화, 다른 브라우저의 같은 사이트, 공백·침묵·불투명·앱 미확인이 낀 변화. |
| 날짜 귀속 | 전환 시각이 속한 계정 시간대 날짜. 날짜는 `[시작, 끝)`이므로 자정 정각의 전환은 다음 날에만 속한다(C2-B11). |

## C3 세션별 사용 대상 전환

**사용자에게**: 집중 세션에서 실제로 작업한 시간 동안 다른 앱·사이트로 바꾼 횟수다.

| 항목 | 내용 |
| --- | --- |
| 정의 | C2 전환 중 전환 시각이 세션의 작업 구간(시작~종료에서 일시중지를 뺀 각 구간) 안에 있는 것. 작업 구간의 시작·끝 순간은 제외(열린 구간). |
| 단위 | 횟수(C2 행 부분집합). 별도 저장 없음. |

## C4 세션 시간 구성

**사용자에게**: 집중 세션의 작업 시간이 의도한 작업·다른 작업·미분류·아직 분류 안 함·비공개·
기록 없음으로 각각 얼마였는지다.

| 항목 | 내용 |
| --- | --- |
| 정의 | 세션 분석 시간과 겹치는 활동 조각을 불투명 → 판정 대기(유효 확정 없음) → 확정 미분류 → 집중(= 세션 라벨) → 이탈(≠ 세션 라벨) 순서로 판정해 합한다. 미관찰 = 세션 분석 시간 − 다섯 합. 집중 이탈 건수를 함께 둔다. |
| 단위 | 초 여섯 개, 이탈 건수, 일시중지 정보 유무. |
| 포함 | 세션 경계에 걸친 구간의 겹친 부분. 0초 이탈 구간(이탈 1건, 0초). 작업 구간은 `[시작, 끝)`이며 0초 구간은 그 시각이 작업 구간 안에 있을 때만 0초 조각이다: 세션 시작·일시중지 종료 시각의 0초 구간은 포함하고, 일시중지 시작·세션 종료 시각의 0초 구간은 제외한다(D10). 열린 활동 구간은 `lastObservedAt`까지만 조각이고 그 뒤는 미관찰이다(FR-6, D10). C5·C6도 같은 조각을 쓴다. |
| 제외 | 일시중지 구간(어떤 값에도 넣지 않음), 진행 중 세션. |
| 불변식 | 여섯 값의 합 = 세션 분석 시간. 사용자가 기록한 `workSeconds`와는 다를 수 있다. |

| C4-B2 | `코딩` 확정 후 구간 version 변경 | 판정 대기 60 |

## C5 방해 앱

**사용자에게**: 집중 세션에서 다른 작업으로 벗어나 있는 동안 어떤 앱·사이트를 몇 번 열었고 거기서
얼마나 머물렀는지다.

| 항목 | 내용 |
| --- | --- |
| 정의 | 진입 횟수: 집중 이탈을 시작하는 이탈 조각은 그 대상에 1회(직전 조각과 같은 대상이어도, D11). 이탈 중에는 이탈 조각의 사용 대상이 직전 조각의 사용 대상과 다르면 그 대상에 1회. 이탈 시간: 이탈 조각 시간을 대상별로 합. |

  입력 계약: 한 계정의 구간은 서로 겹치지 않는다(같은 시각의 0초 구간은 맞닿은 것으로 본다). 하루 읽기
  SQL은 이 전제로 `started_at`에 하한(날짜 시작 전 마지막 구간의 `started_at` 이상, 5단계 Q1b)을 더해
  D1과 같은 행을 고르며, 기록이 길어도 읽는 범위가 늘지 않는다. 이 전제는 관찰 타임라인 projection의
  불변식으로 7단계에서 테스트로 고정한다.
- **D2 이전 대상 체류 시간**: 같은 사용 대상으로 맞닿아 이어진 구간들의 길이 합이다(C2-X1). 하루
  계산은 첫 구간에서 같은 대상으로 맞닿은 앞 구간들을 날짜 밖까지 거슬러 읽는다(C2-B10). 첫 구간은
  D1로 고른 행 중 끝이 있는 첫 행이며, 사용 대상이 없으면(공백·불투명·앱 미확인) 거슬러 읽지 않는다
  (2026-11-13). 그 쿼리 비용은 5단계에서 측정한다(측정 전).
- **D3 0초 이탈**: 집중 이탈 1건(이탈 시간 0초)으로 센다(C4-B6). C2·C7과 같이 0초 구간을 센다.
  실제 0초 구간은 이탈 앱으로 바꾼 직후 관찰이 끊긴 경우이며(M6), 머문 시간은 미관찰로 잡힌다.
  2026-11-12 이 사실을 확인한 뒤에도 유지했다.
- **D4 C5 세부 규칙**: 앱 미확인 이탈은 `앱 미확인` 항목으로 모아 C5 합 = C4 이탈을 지킨다(C5-B4).
  진입 판정의 직전 조각 비교에서 불투명 조각은 건너뛴다(C5-B3).
- **D5 짧은 왕복**: 최소 체류 필터를 두지 않는다(C2-X4). 필터는 저장된 체류 시간으로 조회 때
  추가할 수 있다.
- **D6 철회**: 브라우저 판정을 서버가 bundleId로 추정해도 URL이 없으면 결과가 같다(URL 없는
  브라우저 = 브라우저 앱). 10월 기록의 Safari가 `not_applicable`이었던 원인은 클라이언트에서
  확인한다.
- **D7 eTLD+1이 없는 URL (2026-11-12)**: `http`·`https` URL이면 호스트 그대로(포트 제외)를
  사이트로 둔다(C1-B9). `http`·`https`가 아니거나 호스트가 없는 URL은 브라우저 앱이다(C1-B10).
  이전에는 FR-2가 정하지 않아 골든 비교 도구가 이런 URL에서 실패했다. 10월 기록에는 브라우저
  URL이 없어(Q3) 측정값은 바뀌지 않는다.
- **D8 복귀 없는 이탈의 끝 (2026-11-13)**: 세션 종료 시각이 아니라 세션 분석 시간의 끝이다(C6-B6).
  세션이 일시중지 상태로 끝나면 일시중지 뒤 시간은 이탈로 보지 않는다. FR-16·용어집 「집중 이탈」과
  같고, 이전 C6 정의의 "세션 종료 시각"과의 모순을 없앴다.

## 결정 (2026-11-13)

- **D9 scheme 없는 URL**: Firefox는 주소창 값을 `meet.google.com/x`처럼 scheme 없이 보낸다(기록일
  리허설). URL이 `^[a-z][a-z0-9+.-]*://`로 시작하면(scheme 바로 뒤의 `://`) D7을 그대로 적용한다.
  아니면 `^[a-z][a-z0-9+.-]*:` 뒤 첫 글자가 숫자가 아닐 때(`about:blank`, `mailto:`, `javascript:`,
  `data:`) 비웹이라 브라우저 앱이고, 그 밖(`meet.google.com/x`, `localhost:8000/docs`,
  `192.168.0.1:8080/`, `example.com/?r=https://a.com`)은 `https://`를 붙여 D7을 적용한다(C1-B11·C1-B12).
  scheme은 대소문자를 가리지 않는다(RFC 3986, `About:blank`도 비웹). 원본 URL은 바꾸지 않고 분석에서만
  해석한다.
- **D10 두 독립 구현이 같게 고른 해석**: 4단계 독립 참조 구현(#268)과 프로토타입이 같은 해석을 골랐고
  무작위 비교에서 결과를 가르는 곳을 사례로 고정했다. 작업 구간은 `[시작, 끝)`이라 세션 시작·일시중지
  종료 시각의 0초 구간은 조각이고 일시중지 시작·세션 종료 시각의 0초 구간은 아니다(C4-B7·C4-B8, 다른
  해석이면 무작위 20,000개 중 1,570·1,259개가 바뀜). C5 직전 조각은 미관찰·일시중지를 건너 그 앞
  조각이다(C5-B6, 896개). 앱 미확인 이탈끼리는 다시 진입으로 세지 않는다(C5-B7, 103개). 열린 구간은
  C3~C7에서도 `lastObservedAt`까지다(C4-B9, 444개). C6 이탈 중 전환은 시각이 아니라 구간 순서로 진입·복귀
  전환과 가른다(C6-B7, 198개). 시각으로 가르면 진입·복귀 시각에 놓인 0초 구간 사이의 전환까지 빠진다.
- **D11 C5 진입**: 집중 이탈을 시작하는 이탈 조각은 직전 조각과 사용 대상이 같아도 진입 1회다(C5-B8).
  이전 문언("직전 조각과 다르면 1회")만 따르면 코딩 YouTube → 여가 YouTube처럼 진입이 0인 이탈이 생겨
  불변식 "진입 횟수 합 ≥ 이탈 건수"가 깨지고, C5가 그 이탈이 무엇으로 시작했는지 설명하지 못한다. 이탈
  중에는 직전 조각과 다를 때만 센다. 4단계 비교의 무작위 20,000개 중 292개에서 결과가 바뀌었다.
- **D12 국제화 도메인**: 사이트의 비교·저장 키는 호스트를 IDNA 2003(nameprep, 표준 라이브러리 `idna` 코덱)으로
  바꾼 ASCII 소문자다. 끝의 점은 모두 지운다. 그래서 NFC·NFD 표기, punycode, 전각 문자, 끝 점이 다른 같은
  호스트가 한 사이트로 모인다(C1-B13·C2-B12). PSL 규칙도 같은 방식으로 바꿔 비교한다. 화면 표시는 API·화면이
  키를 유니코드로 바꿔 보여 주며, 분석 출력의 키는 ASCII다. IDNA 변환이 실패하면(63자를 넘는 레이블 등)
  소문자로 바꾸고 끝 점을 지운 호스트 그대로가 키다(C1-B14). 측정 전 가정: ß처럼 IDNA 2003과 2008이 다르게
  다루는 문자가 든 호스트는 표기에 따라 사이트가 갈릴 수 있다(`fußball.com` → `fussball.com`, 브라우저가 만든
  `xn--fuball-cta.com`은 그대로). 실제 브라우저 URL은 대부분 punycode로 와서 영향이 작다고 보며, 기록일 URL에서
  확인한다.
